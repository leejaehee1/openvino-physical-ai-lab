## 4. 반드시 지켜야 할 운영 규칙

### 4-1. Studio 버전 통일

Docker 이미지 태그 기본값이 `IMAGE_TAG=main`이라 **pull한 시각에 따라 버전이 달라집니다** (저장소가 거의 매일 갱신됨).
노트북과 B70 PC의 버전이 다르면 데이터셋·모델 가져오기가 실패할 수 있습니다.

- 오늘 오전에 **반 전체가 같은 시간대에** pull하고, 이후 수업 기간에는 `docker compose pull`을 하지 않습니다.
- 확인: `docker image inspect ghcr.io/open-edge-platform/physical-ai-studio-xpu:main --format '{{index .RepoDigests 0}}'` 출력이 모든 장비에서 같은지 몇 대만 표본 확인
- B70 PC도 같은 다이제스트로 맞춥니다. 다르면 B70 PC에서 다시 pull.

### 4-2. 반 전체 통일 항목 (병합 실패 방지)

| 항목 | 우리 반 기준 (오늘 정해서 칠판에) |
|---|---|
| 프로젝트 이름 | 예: `class_pick` |
| 카메라 이름 | 예: `front` (손목 카메라 쓰면 `gripper`) — 철자까지 동일 |
| 해상도 / fps | 640×480 / 30fps |
| 작업 문구(task) | 예: `Pick up the red cube and place it in the box` |
| 작업대 배치 | 테이프로 로봇 베이스·물체·카메라 위치 표시 |

### 4-3. 2인 1로봇 운영

- 로봇 1대를 노트북 2대가 번갈아 씁니다. **Docker 컨테이너는 시작 시점의 USB 장치만 인식** 하므로, 로봇을 옮겨 꽂을 때마다
  `docker compose down` → USB 연결 → `docker compose up -d` 순서를 지킵니다 (`restart`로는 안 됨).
- 캘리브레이션 값은 **팔(로봇) 기준** 입니다. 같은 팔을 쓰는 두 노트북은 한 명이 캘리브레이션하고, 다른 한 명은 Studio 로봇 등록 시 "Skip verification"으로 보드에서 값을 읽어옵니다. 다른 조의 캘리브레이션 파일을 복사하는 것은 금지.
- 녹화 순서: A가 자기 노트북으로 10개 → 로봇 케이블을 B 노트북으로 → B가 10개. 기다리는 사람은 옆에서 리셋 담당(물체 원위치).

### 4-4. 안전

- 첫 추론은 `--run.duration_s=10`으로 짧게, **한 손은 전원 스위치에**.
- 로봇 동작 범위 안에 손·노트북·컵 두지 않기. 그리퍼에 손가락 넣지 않기.
- 이상 동작 시 즉시 전원 차단 → 캘리브레이션·설정 파일 확인.

## 6. 꼭 전달할 메시지 — 인텔 Physical AI 생태계

> "지금 쓰는 Physical AI Studio는 인텔이 Physical AI 사업을 강화하면서 내놓은 **따끈따끈한 플랫폼** 입니다. 개발 중이라 업데이트가 잦고 가끔 문제도 생기지만, 그만큼 **지금 이 시점에 직접 써 본 경험** 이 앞으로 로봇 생태계에서 의미가 큽니다. 인텔 Physical AI 워크숍에서도 우리 수업과 같은 SO-ARM101로 시연했습니다."

- 버그를 만나면 "망했다"가 아니라 **신기술의 정상적인 모습** 으로 안내. 증상·로그를 기록하게 하면 최종 프로젝트 보고서 소재가 됩니다.
- M3에서 쓴 Anomalib, M2의 OpenVINO와 **같은 Open Edge Platform 계열** 이라는 연결고리를 짚어 주면 과정 전체가 하나로 이어집니다.
- 근거 자료와 질문 대응은 [01](01-physical-ai-intro.md)과 [08 FAQ](08-troubleshooting-faq.md)에 정리.
