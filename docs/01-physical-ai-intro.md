# 01. Physical AI 개관 (89차시)

> 시작 전 [강사 소개](instructor.md) (2분)

## 학습 목표

- Physical AI가 지금까지 배운 비전·언어 AI와 무엇이 다른지 설명할 수 있다.
- 모방학습(Imitation Learning)의 "시연 → 학습 → 재현" 흐름을 이해한다.
- 이번 실습에서 쓰는 도구(Physical AI Studio, LeRobot, OpenVINO)가 각각 어떤 역할인지 안다.
- Intel XPU와 CUDA의 차이를 한 문장으로 말할 수 있다.

## 1. 지금까지 온 길

| 모듈 | 단계 | AI가 하는 일 | 핵심 도구 |
|---|---|---|---|
| M2–M3 | 보는 AI | 이미지를 보고 무엇이 있는지 판단 | OpenVINO 런타임, YOLO, Anomalib |
| M4 | 이해하는 AI | 언어로 판단·설명·도구 호출 | OpenVINO GenAI, RAG, 에이전트 |
| **M5** | ** 움직이는 AI** | ** 카메라와 관절 상태를 보고 다음 동작을 출력** | **Physical AI Studio, LeRobot, OpenVINO** |
| M6 | 통합 | 보고 → 판단하고 → 움직이는 시스템 | 전부 |

세 단계 모두 **OpenVINO가 실행 계층** 이라는 점이 이 과정의 공통 줄기입니다.

## 2. Physical AI란

물리 세계를 **센서로 인식하고, 판단하고, 액추에이터로 직접 행동** 하는 AI입니다.

```text
   관측(Observation)                정책(Policy)              행동(Action)
 ┌─────────────────────┐        ┌──────────────┐        ┌─────────────────┐
 │ 카메라 영상          │ ─────▶ │  신경망 모델   │ ─────▶ │ 6개 관절 목표 각도 │ ──▶ 로봇이 움직임
 │ 현재 관절 각도 6개    │        │ (ACT 등)      │        │ (다음 수십 스텝)   │
 └─────────────────────┘        └──────────────┘        └─────────────────┘
          ▲                                                       │
          └───────────────────── 움직인 결과가 다시 관측됨 ◀─────────┘
```

비전 모델과의 결정적 차이:

| | 비전 모델 (M2–M3) | Physical AI 정책 (M5) |
|---|---|---|
| 출력 | 라벨, 박스, 점수 | **관절 각도(연속값)** |
| 틀리면 | 화면에 잘못된 박스 | **로봇이 실제로 엉뚱하게 움직임** |
| 시간 | 프레임마다 독립 | 앞 행동이 다음 관측을 바꿈 (오차가 누적) |
| 데이터 | 이미지 + 라벨 | **사람의 시연 궤적** (영상 + 관절값 시계열) |

## 3. 모방학습 — 로봇에게 "보여주며" 가르치기

로봇 동작을 규칙으로 일일이 프로그래밍하는 대신, **사람이 직접 시연한 데이터를 모방** 하게 합니다.

1. **시연(Teleoperation)** — 사람이 리더 팔을 손으로 움직이면 팔로워 팔이 똑같이 따라 움직입니다.
2. **녹화** — 그동안 카메라 영상 + 팔로워 관절값(관측)과 리더 관절값(행동)을 함께 저장합니다. 한 번의 시연 = ** 에피소드**.
3. **학습** — "이 장면에서 사람은 이렇게 움직였다"를 신경망이 배웁니다 (지도학습과 같은 구조).
4. **추론** — 리더 팔 없이, 학습된 정책이 카메라를 보고 팔로워를 직접 움직입니다.

SO-ARM101이 **리더·팔로워 2대 1세트** 인 이유가 바로 1번 때문입니다.

### 정책 모델 맛보기

| 정책 | 특징 | 이번 수업 |
|---|---|---|
| **ACT** (Action Chunking with Transformers) | 작고 빠름. 한 번에 수십 스텝의 동작 묶음(chunk)을 예측해 부드럽게 움직임 | ** 사용** — 엣지에서 돌리기 좋은 크기 |
| SmolVLA | 언어 지시를 이해하는 소형 VLA(Vision-Language-Action) | 소개만 |
| Pi0.5 | 대형 VLA, 범용성 높음 | 소개만 |

> VLA = 비전(보고) + 언어(지시를 이해하고) + 행동(움직이는) 모델. M4에서 배운 LLM·VLM이 로봇 제어로 확장된 형태입니다.

## 4. 이번 실습의 도구 지도

| 도구 | 만든 곳 | 역할 |
|---|---|---|
| **SO-ARM101** | TheRobotStudio · Hugging Face | 오픈소스 6자유도 로봇 팔. 리더·팔로워 1세트 |
| **LeRobot** | Hugging Face | 로봇 학습 오픈소스 라이브러리. 데이터셋 형식(LeRobot v3)의 표준 |
| **Physical AI Studio** | Intel (Open Edge Platform) | 로봇·카메라 설정 → 녹화 → 학습 → 내보내기 → 추론을 **GUI 하나로** |
| **physicalai** | Intel (OpenVINO Toolkit) | 학습된 정책을 OpenVINO로 실행하는 런타임 (`physicalai run`) |
| **OpenVINO** | Intel | CPU·GPU·NPU 어디서든 같은 모델을 실행하는 추론 엔진 |

## 5. 왜 인텔 Physical AI Studio인가

- 인텔이 **Physical AI 사업을 강화하며 새로 공개한 플랫폼** 입니다. 2026년 현재 활발히 개발 중이라 거의 매일 업데이트됩니다.
- M3에서 쓴 **Anomalib**, 그리고 Geti 등과 함께 인텔 **Open Edge Platform** 오픈소스 제품군에 속합니다. GitHub 조직 이름도 `open-edge-platform`으로 같습니다.
- LeRobot 데이터셋 형식을 그대로 쓰므로 Hugging Face 로봇 생태계와 호환됩니다. (데이터를 LeRobot으로 가져가 학습해도 됨)
- 학습이 끝나면 **OpenVINO · ONNX · ExecuTorch · PyTorch** 로 자동 내보내기 → 엣지 기기 배포까지 한 흐름.
- 인텔 Physical AI 워크숍 시연에서도 우리와 같은 **SO-ARM101** 을 사용했습니다.

> 신기술이라 버그를 만날 수 있습니다. 그건 실패가 아니라 **최전선에 있다는 증거** 입니다. 어떤 상황에서 어떤 에러가 났는지 기록해 두세요. 최종 프로젝트 발표에서 좋은 소재가 됩니다.

## 6. 우리 교실의 구조 — 학습 서버와 추론 엣지

```text
  학생 노트북 (Meteor Lake, 16GB)          B70 PC (Intel Arc Pro B70)
  ─────────────────────────────           ──────────────────────────
  · 로봇 연결, 텔레오퍼레이션                 · 반 전체 데이터 병합
  · 에피소드 녹화 (데이터 수집)   ── zip ──▶  · ACT 정책 학습
  · OpenVINO 추론 (로봇 구동)    ◀── zip ──  · OpenVINO 모델 내보내기
```

- 노트북 iGPU·NPU로도 추론은 충분하지만, 학습은 오래 걸립니다. 그래서 **학습은 GPU 서버, 추론은 현장 기기** 로 나눕니다.
- 이것이 실제 산업 현장의 운영 구조입니다: 현장 기기가 데이터를 모으고 → 서버가 학습하고 → 다시 현장에 배포.
- 한 사람이 10개씩 모은 에피소드를 **합쳐서 한 번에 학습** 합니다. 반 전체가 협업해서 큰 데이터셋을 만드는 셈입니다. (Studio 권장 최소치는 50 에피소드)

## 7. 자주 나오는 질문 — "CUDA랑 뭐가 달라요?"

짧은 답: **CUDA는 NVIDIA GPU 전용 플랫폼이고, XPU는 PyTorch에서 인텔 GPU를 부르는 이름입니다.** 코드에서는 `"cuda"` 대신 `"xpu"`를 쓰면 되고, 추론은 OpenVINO가 CPU·GPU·NPU를 같은 모델로 실행합니다.

| | NVIDIA | Intel |
|---|---|---|
| 학습 (PyTorch) | `device="cuda"` | `device="xpu"` (PyTorch 2.5부터 공식 지원) |
| 저수준 플랫폼 | CUDA | oneAPI (SYCL, Level Zero) |
| 추론 최적화 | TensorRT | **OpenVINO** (CPU·GPU·NPU 공통) |
| Docker 프로필 | `--cuda` | `--xpu` |

자세한 비교와 장단점은 [08 FAQ](08-troubleshooting-faq.md#cuda와-intel-xpu는-뭐가-다른가요)에 있습니다.

## 정리

- Physical AI = 관측 → 정책 → 행동의 반복. 출력이 **실제 움직임** 이라는 점이 핵심 차이.
- 모방학습 = 사람이 리더 팔로 시연 → 녹화 → 학습 → 정책이 팔로워를 직접 구동.
- 이번 이틀 동안 이 전 주기를 직접 돌립니다.
