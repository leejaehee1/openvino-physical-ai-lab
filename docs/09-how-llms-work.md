# 09. [보충] LLM은 어떻게 만들어지나 — 쉬운 버전

> 일정이 하루 늘어나거나 B70 학습 대기 시간이 길어질 때 쓰는 보충 이론입니다 (약 4차시).
> M4에서 **써 본** 로컬 LLM이 **안에서 무엇을 하는지**, 그리고 그 구조가 ACT·VLA 같은 로봇 정책과 어떻게 이어지는지 봅니다.
> 수식은 최소로 줄였고, 직접 돌려 보는 실습은 numpy만 있으면 됩니다.
> 바탕 교재: 세바스찬 라시카, *밑바닥부터 만들면서 배우는 LLM* (Build a Large Language Model From Scratch) 1–4장 앞부분.

## 학습 목표

- LLM이 하는 일이 결국 **"다음 토큰 맞히기"** 하나라는 것을 설명할 수 있다.
- 텍스트가 **토큰 → 번호 → 벡터** 로 바뀌어 모델에 들어가는 과정을 말할 수 있다.
- **셀프 어텐션** 이 "문장 안에서 누구를 얼마나 참고할지" 정하는 장치라는 것을 이해한다.
- **코잘 마스크** 가 왜 필요한지 로봇의 실시간 제어와 연결해 설명할 수 있다.
- LLM과 ACT·VLA가 **같은 부품(트랜스포머)** 을 쓴다는 것을 안다.

## 진행 순서 (4차시 기준)

| 차시 | 내용 | 절 |
|---|---|---|
| 1 | LLM은 무엇을 배우나 — 다음 토큰 맞히기, 사전 훈련과 미세 튜닝 | 1–2 |
| 2 | 글자를 숫자로 — 토큰화, 입력·타깃, 임베딩 | 3–5 |
| 3 | 셀프 어텐션과 코잘 마스크 — 실습 포함 | 6–8 |
| 4 | GPT 한 장 그림, 로봇 정책과의 연결, 퀴즈 | 9–11 |

## 1. LLM은 딱 한 가지를 배운다 — 다음 토큰 맞히기

> 문장의 앞부분을 보여 주고, **바로 다음에 올 토큰 하나** 를 맞히게 한다.

*"나는 통장을 만들려고 ___에 갔다"* 의 빈칸에 "은행"을 넣으려면, 앞에 나온 "통장", "만들다"의 뜻과 관계를 이미 알고 있어야 합니다. 그래서 **다음 단어 하나를 맞히는 연습이 곧 문맥을 이해하는 연습** 이 됩니다. 이 과제 하나만 엄청나게 많이 연습시켰더니 번역·요약·질의응답까지 할 수 있게 된 것이 오늘날의 LLM입니다.

### 정답 라벨은 누가 다나? — 세 가지 학습 비교

| | M3 YOLO | M5 ACT (모방학습) | LLM 사전 훈련 |
|---|---|---|---|
| 입력 | 이미지 | 영상 + 관절값 | 문장 앞부분 |
| 정답 | 사람이 그린 박스 | 사람이 리더 팔로 한 동작 | **문장의 다음 단어 (이미 글 안에 있음)** |
| 라벨링 비용 | 큼 (한 장씩 그림) | 큼 (한 번씩 시연) | **없음** |
| 이름 | 지도학습 | 지도학습 (행동 복제) | **자기 지도 학습** |

LLM이 인터넷 규모의 글로 학습할 수 있는 이유가 여기 있습니다. **정답이 글 안에 이미 들어 있어서** 사람이 라벨을 달 필요가 없습니다. 반대로 로봇은 정답(동작)을 사람이 직접 보여 줘야 해서, 13일차에 그렇게 공들여 시연을 모은 것입니다.

## 2. 두 단계로 만든다 — 사전 훈련과 미세 튜닝

| 단계 | 하는 일 | 데이터 | 비유 |
|---|---|---|---|
| **사전 훈련** (pre-training) | 다음 토큰 맞히기로 언어 전반을 익힘 | 라벨 없는 대량의 글 | 고등학교까지의 일반 교육 |
| **미세 튜닝** (fine-tuning) | 특정 작업·말투에 맞게 조금 더 학습 | 라벨 있는 적은 데이터 | 입사 후 직무 교육 |

사전 훈련까지 마친 큰 모델을 **파운데이션 모델** 이라고 부릅니다.

| 우리 과정에서 본 같은 패턴 | 사전 훈련된 모델 | 미세 튜닝 |
|---|---|---|
| M3 | COCO로 학습된 YOLO | 내 데이터로 커스텀 검출기 |
| M4 | Qwen·Gemma (이미 학습된 LLM) | (이번 과정에서는 그대로 사용) |
| M5 확장 | SmolVLA·Pi0.5 (대량 로봇 데이터로 사전 훈련) | 우리 반 시연 데이터로 미세 튜닝 가능 |

> **핵심**: 큰 모델을 처음부터 만드는 것은 비싸고, 대부분의 현장은 **잘 만들어진 파운데이션 모델을 가져와 미세 튜닝** 합니다. 엣지에서는 거기에 **양자화(INT8·INT4)** 를 더해 가볍게 만듭니다(M2·M4).

## 3. 글자를 숫자로 ① — 토큰화

컴퓨터는 글자를 그대로 계산할 수 없으므로, 먼저 글을 **토큰** 이라는 조각으로 자르고 조각마다 **번호(토큰 ID)** 를 붙입니다.

```text
"로봇이 큐브를 집는다"
   ↓ 자르기
["로봇이", "큐브를", "집는다"]
   ↓ 어휘사전에서 번호 찾기
[2, 6, 5]
```

### 어휘사전에 없는 단어는?

단어 단위로 자르면 처음 보는 단어가 나올 때 막힙니다. 그래서 GPT 계열은 **BPE(Byte Pair Encoding)** 를 씁니다.

- 자주 함께 나오는 글자 조각을 하나로 합쳐 가며 어휘사전을 만듭니다. ("로" + "봇" → "로봇")
- 처음 보는 단어도 **더 작은 조각들로 쪼개서** 표현할 수 있습니다. 끝까지 쪼개면 글자 한 개, 바이트 한 개까지 내려갑니다.
- GPT-2의 어휘사전은 **50,257개** 토큰입니다.

> 한국어가 영어보다 토큰을 더 많이 쓰는 경우가 많습니다. 같은 문장도 토큰이 많으면 **느리고 비쌉니다**. M4에서 한국어 답변이 영어보다 느리게 느껴졌다면 이 때문일 수 있습니다.

### [보충] 로봇의 동작도 토큰이 될 수 있다

일부 VLA 모델(예: RT-2)은 관절이나 그리퍼의 연속값을 **256칸 같은 구간으로 나눠 번호를 붙이고**, 그 번호를 LLM이 단어처럼 출력하게 만듭니다. "말을 만드는 모델"이 "동작을 만드는 모델"로 바뀌는 방법 중 하나입니다.

## 4. 글자를 숫자로 ② — 입력과 타깃 만들기

다음 토큰 맞히기 연습 문제는 글을 **한 칸씩 밀어서** 자동으로 만듭니다(슬라이딩 윈도).

| 입력 (문맥 길이 3) | 타깃 (한 칸 뒤) |
|---|---|
| 로봇이 큐브를 집는다 | 큐브를 집는다 **로봇이** |
| 큐브를 집는다 로봇이 | 집는다 로봇이 **큐브를** |
| 집는다 로봇이 큐브를 | 로봇이 큐브를 **상자에** |

입력의 각 자리마다 "그다음 토큰"이 정답이라서, 한 줄에서 **문맥 길이만큼의 연습 문제** 가 한꺼번에 나옵니다.

### 13일차 데이터와 비교

| | LLM | ACT |
|---|---|---|
| 입력 | 앞의 토큰들 | 지금의 영상 + 관절값 |
| 정답 | **다음 토큰** | **다음 수십 스텝의 동작** (action chunk) |
| 한 번에 예측 | 보통 1개씩 이어서 | 여러 개를 한꺼번에 |
| 데이터 만드는 법 | 글을 한 칸씩 밀기 | 시연을 프레임 단위로 자르기 |

ACT의 "앞으로 k스텝을 한꺼번에 예측"은 LLM의 "다음 토큰 예측"을 **동작의 시간축** 으로 옮겨 온 것이라고 볼 수 있습니다.

## 5. 글자를 숫자로 ③ — 임베딩

토큰 ID(2, 6, 5)는 그냥 이름표라서 "2와 6이 비슷한가?" 같은 계산이 의미가 없습니다. 그래서 번호마다 **여러 개의 숫자로 된 벡터** 를 하나씩 배정합니다. 이것이 **토큰 임베딩** 입니다.

```text
토큰 ID 2 ("로봇이")  →  [ 0.21, -0.43, 0.88, 0.05, … ]   ← 표에서 2번째 줄을 꺼냄
```

- 임베딩은 거대한 **표에서 줄 하나를 꺼내는 것(룩업)** 입니다. 표의 값은 처음엔 무작위이고, **학습하면서 바뀝니다.**
- 학습이 끝나면 뜻이 비슷한 토큰끼리 **벡터도 가까워집니다**.
- GPT-2 small은 토큰 하나를 **768개 숫자** 로 표현합니다.

### 순서 정보 더하기 — 위치 임베딩

"로봇이 큐브를 집는다"와 "큐브를 로봇이 집는다"는 같은 토큰들이지만 뜻이 다릅니다. 그런데 뒤에서 볼 어텐션은 **순서를 모릅니다**. 그래서 **자리마다 위치 벡터를 하나 더 만들어 더해 줍니다.**

```text
입력 임베딩 = 토큰 임베딩 (무엇인가) + 위치 임베딩 (몇 번째인가)
```

> ACT도 트랜스포머를 쓰기 때문에, 이미지 조각과 동작 순서에 **위치 정보** 를 넣어 줍니다. 같은 문제를 같은 방식으로 풉니다.

## 6. 셀프 어텐션 — 문장 안에서 누구를 참고할까

### 6-1. 왜 필요한가

*"로봇이 큐브를 집어서 **그것** 을 상자에 넣었다"* 에서 "그것"이 무엇인지 알려면 앞의 "큐브"를 봐야 합니다. **각 토큰이 문장 안의 다른 토큰들을 얼마나 참고할지 스스로 정하는 장치** 가 셀프 어텐션입니다.

### 6-2. 세 단계

| 단계 | 하는 일 | 쉬운 말로 |
|---|---|---|
| ① 점수 | 지금 토큰과 다른 토큰들의 **점곱** | 얼마나 닮았나 (관련 있나) |
| ② 가중치 | 점수를 **소프트맥스** 로 바꿈 | 합이 1인 비율로 (몇 %씩 참고할지) |
| ③ 문맥 벡터 | 비율대로 다른 토큰 벡터를 **섞음** | 주변을 참고해 업그레이드된 내 벡터 |

```text
"그것"의 가중치:  로봇이 10% · 큐브를 70% · 집어서 5% · 그것 10% · 상자에 5%
"그것"의 새 벡터 = 0.10×로봇이 + 0.70×큐브를 + 0.05×집어서 + …   ← "큐브"의 뜻이 많이 섞임
```

### 6-3. 쿼리·키·값 — 도서관에서 책 찾기

단순한 방식은 **자기 자신과 가장 닮았으니 자기만 보는** 경향이 있습니다(실습 4단계에서 직접 확인). 그래서 실제 모델은 각 토큰을 세 가지 역할의 벡터로 바꿔서 씁니다.

| 역할 | 도서관 비유 | 하는 일 |
|---|---|---|
| **쿼리 (Q)** | 내가 찾는 질문 | "나는 지금 무엇을 찾고 있나" |
| **키 (K)** | 책등의 제목·색인 | "나는 이런 내용이라고 광고함" |
| **값 (V)** | 책의 실제 내용 | 선택되면 실제로 전달되는 정보 |

- 점수 = **내 쿼리 · 상대의 키** (질문과 색인이 얼마나 맞나)
- 결과 = 점수 비율대로 **상대의 값** 을 섞음
- 점수를 **√(키 길이)로 나눠** 숫자가 너무 커지지 않게 합니다(스케일드 점곱 어텐션). 너무 크면 소프트맥스가 한쪽으로 쏠려 학습이 잘 안 됩니다.

Q·K·V를 만드는 행렬은 **학습되는 값** 입니다. 학습을 통해 "무엇을 찾을지", "어떻게 보일지"를 모델이 스스로 배웁니다.

## 7. 코잘 마스크 — 미래는 볼 수 없다

다음 토큰을 맞히는 연습인데 **정답(뒤쪽 토큰)을 볼 수 있으면** 연습이 되지 않습니다. 그래서 각 토큰은 **자기와 자기 앞 토큰만** 볼 수 있게 가립니다.

```text
          로봇이  큐브를  집는다
로봇이      ✅      ✖      ✖
큐브를      ✅      ✅      ✖
집는다      ✅      ✅      ✅      ← 대각선 위쪽(미래)은 가중치 0
```

- 구현할 때는 미래 칸의 점수를 **−∞로 바꾼 뒤 소프트맥스** 를 하면 그 칸이 정확히 0이 되고, 나머지는 자동으로 합이 1이 됩니다.
- 이런 모델을 GPT처럼 **디코더 전용(decoder-only)** 모델이라고 합니다. 문장 전체를 앞뒤로 다 보는 BERT 같은 모델과 구분됩니다.

> **로봇과 같은 원리**: 로봇 정책도 실행 중에는 **아직 오지 않은 미래 프레임을 볼 수 없습니다.** 학습 때 미래 정보를 몰래 쓰면 실제 실행에서는 성능이 무너집니다. 05a에서 본 "데이터 누수"와도 같은 이야기입니다.

### 덧붙여 — 드롭아웃

학습 중에만 어텐션 가중치 일부를 **무작위로 0으로** 만들어, 특정 연결에만 기대지 않게 합니다(과대적합 방지). 남은 값은 그만큼 키워서 평균을 유지하고, **추론할 때는 끕니다.**

```bash
python3 scripts/mini_llm_demo.py
```

| 단계 | 화면에서 볼 것 | 질문 |
|---|---|---|
| 1. 토큰화 | 어휘사전과 토큰 ID | "로봇이"는 몇 번? 같은 단어는 같은 번호인가? |
| 2. 입력과 타깃 | 한 칸씩 밀린 쌍 | 문장 하나에서 연습 문제가 몇 개 나왔나? |
| 3. 임베딩 | (3, 4) 모양의 숫자 표 | 3과 4는 각각 무엇의 개수인가? |
| 4. 단순 어텐션 | 대각선이 큰 가중치 표 | 왜 자기 자신을 가장 많이 볼까? (→ 6-3) |
| 5. 코잘 어텐션 | 대각선 위가 0인 표 | 첫 번째 토큰은 왜 항상 자기만 100% 보나? |
| 6. 규모 감각 | FP32 ~ INT4 용량 | 노트북에 올리려면 어떤 형식이 좋을까? |

> 경험자: `emb_dim`, `context`, `d_k`를 바꿔 보고 모양이 어떻게 달라지는지 확인하세요. 문장을 바꿔 자기 프로젝트의 지시문으로 실험해 봐도 좋습니다.

## 9. GPT 한 장 그림

```text
 텍스트 ──▶ 토큰화 ──▶ 토큰 ID
                         │
                         ▼
          토큰 임베딩 + 위치 임베딩
                         │
             ┌───────────▼───────────┐
             │  트랜스포머 블록 × 12   │
             │  ┌──────────────────┐ │
             │  │ 층 정규화          │ │
             │  │ 멀티 헤드 어텐션   │ │  ← 6–7절 (코잘 마스크 포함)
             │  │ + 숏컷 연결        │ │
             │  │ 층 정규화          │ │
             │  │ 피드 포워드 (GELU) │ │
             │  │ + 숏컷 연결        │ │
             │  └──────────────────┘ │
             └───────────┬───────────┘
                         ▼
             최종 층 정규화 → 출력층
                         │
                         ▼
        어휘사전 50,257개 각각의 점수(로짓) → 가장 그럴듯한 다음 토큰
```

| 부품 | 한 줄 설명 |
|---|---|
| **멀티 헤드 어텐션** | 어텐션을 여러 개(GPT-2는 12개) 나란히 돌려, 문법·의미·지시 대상 등 **여러 관점** 으로 동시에 참고 |
| **층 정규화** | 각 토큰 벡터의 숫자 범위를 고르게 맞춰 학습을 안정시킴 |
| **피드 포워드 + GELU** | 어텐션으로 모은 정보를 토큰마다 한 번 더 가공. GELU는 ReLU를 부드럽게 만든 활성화 함수 |
| **숏컷 연결** | 블록의 입력을 출력에 그대로 더해 줌. 층이 깊어도 학습 신호(그레이디언트)가 사라지지 않게 하는 지름길 |

### GPT-2 small(124M) 설정

| 항목 | 값 |
|---|---|
| 어휘사전 크기 | 50,257 |
| 문맥 길이 | 1,024 토큰 |
| 임베딩 차원 | 768 |
| 어텐션 헤드 | 12 (헤드 하나당 64) |
| 블록 수 | 12 |
| 파라미터 | 약 1억 2,400만 개 |

### 엣지에서의 무게

| 형식 | 124M 모델 가중치 용량 |
|---|---|
| FP32 | 약 496 MB |
| FP16 | 약 248 MB |
| INT8 | 약 124 MB |
| INT4 | 약 62 MB |

M4에서 쓴 소형 LLM은 보통 수억~수십억 파라미터로, 이보다 몇 배에서 수십 배 큽니다. 그래서 **INT4 가중치 압축**(OpenVINO GenAI)이 노트북에서 필수였던 것입니다.

## 10. 로봇 정책과의 연결 — 같은 부품, 다른 출력

| | GPT (M4) | ACT (M5) | VLA (SmolVLA·Pi0.5) |
|---|---|---|---|
| 입력 | 토큰 | 이미지 특징 + 관절값 | 이미지 + 언어 지시 + 관절값 |
| 핵심 부품 | 트랜스포머 디코더 | 트랜스포머 인코더-디코더 | 비전 인코더 + 언어 모델 + 행동 출력부 |
| 출력 | 다음 토큰 | 다음 k스텝의 관절값 | 다음 동작 (또는 동작 묶음) |
| 학습 데이터 | 대량의 글 (자기 지도) | 우리 반 시연 (지도) | 대량 로봇 시연으로 사전 훈련 + 미세 튜닝 |
| 엣지 실행 | OpenVINO GenAI, INT4 | OpenVINO (physicalai) | 크기 때문에 최적화 필수 |

> **정리**: 어텐션은 "문장 안에서 누구를 참고할지"를 정하는 장치였습니다. 로봇 정책에서는 같은 장치가 **"화면의 어디를, 어느 관절 상태를 참고할지"** 를 정합니다. M4와 M5는 서로 다른 기술이 아니라, **같은 트랜스포머를 언어와 동작에 각각 쓴 것** 입니다.

## 11. 자기점검

1. LLM 사전 훈련에 사람이 라벨을 달 필요가 없는 이유는? 로봇 모방학습은 왜 다른가요?
2. 토큰 ID를 그대로 쓰지 않고 임베딩 벡터로 바꾸는 이유는?
3. 위치 임베딩이 없으면 어떤 문제가 생기나요?
4. 셀프 어텐션의 세 단계(점수 → 가중치 → 문맥 벡터)를 쉬운 말로 설명해 보세요.
5. 쿼리·키·값을 도서관에 비유하면 각각 무엇인가요?
6. 코잘 마스크가 없으면 학습에서 어떤 일이 생기고, 로봇 정책에서는 무엇과 같은 문제인가요?
7. 124M 모델을 INT4로 바꾸면 용량이 대략 얼마나 줄어드나요?

<details>
<summary>모범 답안</summary>

1. 다음 단어라는 정답이 글 안에 이미 들어 있기 때문입니다(자기 지도 학습). 로봇은 "어떤 동작이 정답인지"가 데이터에 저절로 들어 있지 않아 사람이 시연으로 보여 줘야 합니다.
2. 번호는 이름표일 뿐이라 비슷함을 계산할 수 없습니다. 벡터로 바꾸면 뜻이 비슷한 토큰끼리 가까워지도록 학습할 수 있습니다.
3. 어텐션은 순서를 모르기 때문에 "로봇이 큐브를"과 "큐브를 로봇이"를 구분하지 못합니다.
4. 다른 토큰과 얼마나 관련 있는지 점수를 매기고, 그 점수를 합이 1인 비율로 바꾼 뒤, 비율대로 다른 토큰들의 정보를 섞어 내 벡터를 업데이트합니다.
5. 쿼리 = 내가 찾는 질문, 키 = 책의 제목·색인, 값 = 책의 실제 내용.
6. 정답(뒤쪽 토큰)을 보고 맞히게 되어 실제로는 아무것도 배우지 못합니다. 로봇에서 미래 프레임을 학습에 몰래 쓰는 데이터 누수와 같은 문제입니다.
7. FP32 약 496MB → INT4 약 62MB, 약 8분의 1입니다.

## 용어 사전

| 용어 | 뜻 |
|---|---|
| 토큰 | 모델이 다루는 글의 최소 조각 |
| 토큰화 / BPE | 글을 토큰으로 자르는 과정 / 자주 붙는 조각을 합쳐 가며 어휘사전을 만드는 방식 |
| 어휘사전 | 토큰과 번호의 대응표. GPT-2는 50,257개 |
| 자기 지도 학습 | 데이터 안에 이미 있는 정보를 정답으로 쓰는 학습 |
| 사전 훈련 / 미세 튜닝 | 대량 데이터로 일반 능력을 익힘 / 적은 데이터로 특정 작업에 맞춤 |
| 파운데이션 모델 | 사전 훈련을 마쳐 여러 작업의 출발점이 되는 큰 모델 |
| 임베딩 | 토큰 번호를 학습 가능한 벡터로 바꾼 것 |
| 위치 임베딩 | 토큰이 몇 번째인지 알려 주기 위해 더하는 벡터 |
| 셀프 어텐션 | 같은 입력 안의 토큰들이 서로를 얼마나 참고할지 정해 정보를 섞는 장치 |
| 쿼리·키·값 | 찾는 질문 · 광고하는 색인 · 전달되는 내용 |
| 코잘 마스크 | 미래 토큰을 보지 못하게 가리는 장치 |
| 멀티 헤드 어텐션 | 어텐션을 여러 개 나란히 돌려 여러 관점으로 참고하는 방식 |
| 트랜스포머 블록 | 어텐션 + 피드 포워드 + 정규화 + 숏컷 연결의 묶음 |
| 로짓 | 어휘사전의 각 토큰에 매긴 점수. 소프트맥스를 거치면 확률이 됨 |
