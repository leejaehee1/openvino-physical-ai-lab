# 07. 최종 프로젝트 (105–120차시 · 14–15일차)

## 목표

지금까지 만든 부품 — **보는 AI(M2·M3) · 이해하는 AI(M4) · 움직이는 AI(M5)** — 를 조합해 ** 인식 → 판단 → 행동**이 연결된 온디바이스 시스템을 만들고 시연합니다.

## 일정

| 차시 | 단계 | 산출물 |
|---|---|---|
| 105–108 | 기획과 설계 | 주제, 요구사항, 파이프라인 그림, 역할 분담 |
| 109–112 | 구현 ① 인식 계층 | 비전 모델이 실시간으로 동작하고 결과를 다음 단계로 넘김 |
| 113–116 | 구현 ② 판단·행동 계층 | LLM 연계 또는 로봇 제어 연동 |
| 117–120 | 발표 | 통합 테스트, 라이브 시연, 발표, 상호 평가 |

## 1. 방향 선택

| 방향 | 내용 | 예시 |
|---|---|---|
| **A. 로봇 중심 (작업 자동화)** | 비전이 상황을 판단 → 로봇이 정책으로 행동 | YOLO로 물체 색·종류 인식 → 해당 작업 정책 실행 |
| **B. 비전 중심 (검사 자동화)** | 비전·이상탐지가 판정 → LLM이 리포트, 로봇은 선택 | Anomalib으로 불량 판정 → 로봇이 불량품을 옆으로 치움 → LLM이 검사 리포트 작성 |

> 로봇이 2인 1대이므로 **로봇 사용 시간표** 를 조별로 미리 정합니다. 로봇 없이 되는 인식·판단 계층을 먼저 완성하고, 로봇 연동은 정해진 시간에 몰아서 합니다.

## 2. 주제 예시

| 난이도 | 주제 | 인식 | 판단 | 행동 |
|---|---|---|---|---|
| ★ | 물체가 보이면 집어 옮기기 | YOLO (M3) | 규칙: 물체 있으면 실행 | ACT 정책 1개 (M5) |
| ★★ | 색깔별 분류 | YOLO 클래스 | 규칙: 빨강→A, 파랑→B | 위치별 ACT 정책 2개 또는 녹화 시 위치 다양화 |
| ★★ | 불량품 골라내기 | Anomalib (M3) | 임계값 판정 | ACT "치우기" 정책 |
| ★★★ | 말로 시키는 로봇 | VLM/YOLO | 로컬 LLM이 지시를 해석해 도구 호출 (M4 에이전트) | 도구 = 정책 실행 함수 |
| ★★★ | 검사 + 리포트 | Anomalib | LLM이 결과 요약, RAG로 검사 기준 조회 (M4) | 로봇 분류 + 리포트 출력 |

### ★★★ 구조 예: LLM 에이전트가 로봇 정책을 도구로 호출

```text
"빨간 블록 상자에 넣어줘"
        │
        ▼
  로컬 LLM (OpenVINO GenAI, M4)
   도구 목록: detect_objects(), run_policy(name), report()
        │ tool call
        ▼
  detect_objects()  → YOLO (OpenVINO)  → "red_cube at (x, y)"
  run_policy("pick_red") → physicalai run --config pick_red.yaml
        │
        ▼
  결과를 LLM이 자연어로 보고
```

M4에서 배운 대로 **도구는 3–4개로 제한** 해야 소형 모델에서도 안정적입니다.

## 3. 기획서 양식 (105–108차시 제출)

```markdown
# 조 이름 / 조원

## 1. 한 줄 소개
## 2. 해결하려는 문제 (현장 시나리오)
## 3. 시스템 구성도
   카메라 → [인식: 모델명] → [판단: 규칙/LLM] → [행동: 로봇/출력]
## 4. 사용할 모델과 디바이스
   | 계층 | 모델 | 실행 디바이스(CPU/GPU/NPU) | 이유 |
## 5. 필요한 데이터 (새로 수집할 것 / 재사용할 것)
## 6. 역할 분담
## 7. 성공 기준 (숫자로: 예) 10회 중 7회 성공)
## 8. 위험 요소와 대안 (예: 정책이 불안정하면 → 데모 영상 백업)
```

## 4. 구현 팁

- **인식 계층 먼저 단독으로 완성** — 웹캠 실시간으로 결과가 나오고, 그 결과를 함수 반환값이나 파일로 넘길 수 있게.
- 계층 사이 연결은 단순하게: 함수 호출, JSON 파일, 또는 `subprocess`로 `physicalai run` 실행.
- 새 정책이 필요하면 **13일차와 같은 절차**(녹화 → B70 학습 → 배포)를 따릅니다. B70 학습 줄이 길어지므로 **14일차 오후 2시 전까지** zip 제출.
- 디바이스 배분 고민: YOLO는 NPU, LLM은 GPU, 정책은 GPU/CPU … 같은 분산 배치는 **좋은 발표 포인트** 입니다.

## 5. 발표 (117–120차시)

조당 10분 (발표 6분 + 시연 3분 + 질의 1분)

1. 문제와 시나리오
2. 시스템 구성도 — 어떤 모델이 어떤 디바이스에서 도는지
3. **라이브 시연** (실패 대비 녹화 영상 준비)
4. 성능 수치 (성공률, 추론 속도)
5. 겪은 문제와 해결 — 신기술 플랫폼을 쓰며 만난 이슈도 좋은 소재
6. 실제 현장이라면 무엇을 더 해야 하나
