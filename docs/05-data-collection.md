# 05. 데이터 수집 (97–100차시)

> 왜 이렇게 녹화해야 하는지(분포 이동, 다봉성, 커버리지 등)는 [05a 데이터 수집 이론](05a-data-collection-theory.md)에 자세히 정리했습니다.

## 학습 목표

- 좋은 시연 에피소드의 조건을 알고 1인 10개를 녹화한다.
- 불량 에피소드를 골라내고 데이터셋을 zip으로 내보낸다.
- LeRobot v3 데이터셋 구조를 이해하고, 왜 그냥 복사하면 안 되고 병합해야 하는지 설명할 수 있다.

## 1. 오늘의 작업

| 항목 | 값 (강사가 칠판에 확정) |
|---|---|
| 작업 문구 (task) | 예: `Pick up the red cube and place it in the box` — **반 전체가 글자 하나 다르지 않게** |
| 데이터셋 이름 | `s<학생번호>_pick` (예: `s05_pick`) |
| 에피소드 수 | 1인 **10개** (불량 삭제 후 기준) |
| 에피소드 길이 | 10–20초 정도 |

## 2. 좋은 에피소드의 조건

모델은 **보여준 것만큼만** 배웁니다. 10개라도 깨끗하면 20개의 지저분한 데이터보다 낫습니다.

| ✅ 좋은 시연 | ❌ 나쁜 시연 |
|---|---|
| 매번 **같은 시작 자세** 에서 출발 | 시작 자세가 제각각 |
| 일정한 속도로 **망설임 없이** | 중간에 멈칫하거나 되돌아감 |
| 물체를 **한 번에** 집음 | 여러 번 헛집기 |
| 끝나면 정해진 자세로 복귀 | 작업 끝나고 아무 데서나 멈춤 |
| 카메라에 팔·물체가 **가려지지 않음** | 사람 손·몸이 화면에 들어옴 |
| 물체 위치를 **표시 근처에서 조금씩** 바꿈 | 항상 완전히 같은 위치 (일반화 안 됨) 또는 표시 밖 |

> 물체 위치를 매번 **표시 안에서 1–2cm씩** 바꿔 주면, 모델이 "물체를 보고 찾아가는" 법을 배웁니다. 완전히 같은 위치만 녹화하면 위치를 외워 버립니다.

## 3. 녹화하기

1. **Datasets(데이터셋)** → New dataset(새 데이터셋) → 환경 선택 → 이름 `s05_pick` → 작업 문구 입력
2. 데이터셋 열기 → **Add episode**(에피소드 추가) → 카메라 화면과 로봇 시각화가 뜰 때까지 대기
3. 녹화 루프:

```text
① 장면 리셋 (물체를 표시 위치에, 팔은 시작 자세)
② 작업 문구 확인
③ Start episode  (→ 키)
④ 시연
⑤ Accept (→ 키)  또는  Discard (← 키)
```

- 오른쪽 위에 지금까지 녹화한 에피소드 수가 표시됩니다.
- 짝꿍이 ① 리셋을 맡아 주면 훨씬 빠릅니다.
- 녹화 중 실수하면 끝까지 억지로 하지 말고 **Discard 후 다시**.

## 4. 품질 점검

녹화를 마치면 데이터셋 화면에서 에피소드를 하나씩 확인합니다.

- 에피소드를 재생해 **모든 카메라 영상이 나오는지**
- 관절값 그래프에서 **튀는 구간·평평하게 멈춘 긴 구간** 이 있는지
- **첫 프레임 자세가 다른 에피소드와 같은지**

이상한 에피소드는 삭제하고 다시 녹화해 **10개를 채웁니다**.

## 5. 내보내기와 제출

1. 데이터셋 화면 → **Export dataset**(데이터셋 내보내기) → zip 다운로드
2. 파일 이름을 `s05.zip`처럼 **학생 번호로** 변경
3. 강사가 안내한 공유폴더(또는 USB)에 넣기

## 6. LeRobot v3 데이터셋 구조 — 왜 병합이 필요한가

zip을 풀어 보면 이런 구조입니다.

```text
s05_pick/
├── meta/
│   ├── info.json        ← fps, 카메라 이름·해상도, 관절 이름, 로봇 종류, 에피소드 수
│   ├── stats.json       ← 관절값·이미지의 평균·표준편차 (정규화에 사용)
│   ├── tasks.parquet    ← 작업 문구 목록
│   └── episodes/        ← 에피소드별 시작·끝 위치 색인
├── data/
│   └── chunk-000/file-000.parquet     ← 10개 에피소드의 관절값이 한 파일에 이어 붙어 있음
└── videos/
    └── observation.images.front/
        └── chunk-000/file-000.mp4     ← 10개 에피소드 영상이 한 파일에 이어 붙어 있음
```

한 행(프레임) 안에 들어 있는 것:

| 키 | 내용 | 역할 |
|---|---|---|
| `observation.state` | 팔로워의 현재 관절값 6개 | 모델 입력 |
| `observation.images.front` | 그 순간의 카메라 프레임 | 모델 입력 |
| `action` | 리더의 관절값 6개 (= 사람이 시킨 동작) | **모델이 맞혀야 할 정답** |
| `episode_index`, `frame_index`, `timestamp` | 몇 번째 에피소드의 몇 번째 프레임인지 | 색인 |

그래서 학생 zip을 한 폴더에 **그냥 복사하면 안 됩니다**.

- 모두 `episode 0–9`, `file-000.parquet`이라 **서로 덮어씁니다**.
- `info.json`의 에피소드 수, `stats.json`의 통계를 **전체 데이터 기준으로 다시 계산** 해야 합니다. 특히 통계가 틀리면 **에러 없이 성능만 나빠져서** 원인을 찾기 어렵습니다.

→ 강사가 B70 PC에서 **병합 명령** 으로 번호를 다시 매기고 메타·통계를 새로 계산합니다. ([06 교안](06-act-train-and-inference.md))

## 더 해보기 (경험자)

에피소드 품질을 숫자로 한 번에 보려면 [`scripts/analyze_episodes.py`](../scripts/analyze_episodes.py)를 실행합니다 (길이, 시작 자세 편차, 정지 비율, 추종 오차). 설명은 [05a 7절](05a-data-collection-theory.md).

```bash
python3 scripts/analyze_episodes.py ~/peek
```

내보낸 zip을 풀어 직접 열어 봅니다.

```bash
mkdir -p ~/peek && cd ~/peek && unzip -q ~/Downloads/s05.zip
python3 -c "import json; d=json.load(open('meta/info.json')); print(d['fps'], d['total_episodes'], list(d['features']))"
```

```python
import pandas as pd
df = pd.read_parquet("data/chunk-000/file-000.parquet")
print(df.groupby("episode_index").size())    # 에피소드별 프레임 수
print(df["action"].iloc[0], df["observation.state"].iloc[0])
```

- 에피소드별 프레임 수가 들쭉날쭉하면 → 시연 시간이 제각각이라는 뜻
- `action`과 `observation.state`의 차이 → 팔로워의 추종 오차
