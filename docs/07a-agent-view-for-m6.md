## 1. 우리가 만드는 AI는 어떤 AI인가

### 1-1. AI를 보는 네 가지 관점

AI를 정의하는 방법은 두 가지 질문으로 나눌 수 있습니다. **생각을 볼 것인가, 행동을 볼 것인가?** 그리고 **사람을 기준으로 할 것인가, 합리성을 기준으로 할 것인가?**

| | 사람을 기준으로 | 합리성을 기준으로 |
|---|---|---|
| **생각** | 사람처럼 생각하기 (인지과학) | 올바르게 추론하기 (논리) |
| **행동** | 사람처럼 행동하기 (튜링 테스트) | **합리적으로 행동하기** ← 이 과정의 목표 |

우리 로봇은 사람처럼 생각할 필요도, 사람인 척할 필요도 없습니다. **주어진 목표(물체를 상자에 넣기)를 가장 잘 달성하는 행동** 을 고르면 됩니다. 이것을 **합리적 에이전트(rational agent)** 라고 부르고, 오늘 이후 모든 설계의 기준이 됩니다.

### 1-2. Total Turing Test — 우리가 15일 동안 쌓은 것

튜링 테스트는 "대화만으로 사람과 구별되지 않는가"를 봅니다. 여기에 **보고 만지는 능력** 까지 요구하는 것이 **Total Turing Test** 입니다.

| Total Turing Test가 요구하는 능력 | 이 과정에서 배운 곳 |
|---|---|
| 자연어 처리 — 말을 이해하고 답하기 | M4 로컬 LLM, RAG |
| 지식 표현과 추론 — 아는 것을 저장하고 결론 내기 | M4 RAG, 에이전트 (오늘 6절) |
| 기계 학습 — 경험으로 나아지기 | M3 YOLO·Anomalib, M5 모방학습 |
| **컴퓨터 비전 — 보기** | M2–M3 |
| **로보틱스 — 물체를 조작하기** | M5 SO-101 |

> 우리가 지금까지 따로따로 배운 것들이, 원래 "지능"의 정의 안에서는 **한 세트** 였습니다. M6는 이것을 다시 한 세트로 묶는 단계입니다.

### 1-3. 규칙에서 데이터로 — 우리 과정이 서 있는 자리

| 시기 | 주된 방식 | 한계 | 우리 과정에서 |
|---|---|---|---|
| 초기 AI, 전문가 시스템 | 사람이 **규칙** 을 직접 써 넣음 | 규칙이 끝없이 늘어나고, 예외에 약함 | M6 판단 계층의 규칙 기반 방식 |
| 기계 학습의 확산 | **데이터** 에서 패턴을 학습 | 좋은 데이터를 모으는 비용 | M3 YOLO, M5 모방학습 |
| 대규모 데이터와 모델 [보충] | 거대한 사전학습 모델을 가져와 씀 | 계산 자원, 엣지 배포 | M4 LLM, VLA(SmolVLA·Pi0.5) |

**규칙이 사라진 것은 아닙니다.** 현장 시스템은 대개 **학습된 모델 위에 규칙(특히 안전 규칙)을 얹는** 혼합 구조입니다. 6절에서 다시 봅니다.

## 2. 에이전트와 합리성 — SO-101은 어떤 에이전트인가

### 2-1. 에이전트 = 센서로 지각하고 액추에이터로 행동하는 것

```text
            지각(percept)                       행동(action)
  환경 ──▶ [센서] ──▶ [ 에이전트 프로그램 ] ──▶ [액추에이터] ──▶ 환경
   ▲                                                         │
   └────────────────── 행동이 환경을 바꾼다 ◀──────────────────┘
```

| 에이전트 요소 | SO-101 + ACT (13일차) |
|---|---|
| 센서 | USB 카메라(front), 6개 서보의 위치 센서 |
| 지각 | 한 프레임의 영상 + 관절값 6개 |
| 에이전트 프로그램 | ACT 정책 (OpenVINO로 실행) |
| 액추에이터 | STS3215 서보 6개 |
| 행동 | 6개 관절의 목표 위치 (다음 수십 스텝) |

### 2-2. 에이전트 함수와 에이전트 프로그램

- **에이전트 함수**: "지금까지의 지각 이력 → 행동"이라는 **수학적 대응 관계** (추상적인 설계도)
- **에이전트 프로그램**: 그 함수를 실제 하드웨어에서 돌리는 **코드** (구현)

13일차에 B70에서 만든 것은 **에이전트 프로그램** 입니다. 사람의 시연 데이터는 "이 지각에는 이 행동"이라는 **에이전트 함수의 샘플** 이었고, 학습은 그 샘플로 프로그램을 만드는 과정이었습니다.

### 2-3. 합리성은 성능 척도로 정의된다

**합리적 에이전트** 란 지금까지의 지각과 사전 지식을 바탕으로 **성능 척도의 기대값을 최대로 만드는 행동** 을 고르는 에이전트입니다. 합리성을 정하는 네 가지는 다음과 같습니다.

| 요소 | SO-101 집기 작업에서 |
|---|---|
| 성능 척도 | 10회 중 상자에 넣은 횟수, 걸린 시간, 충돌 없음 |
| 사전 지식 | 작업대 배치, 캘리브레이션, 학습된 정책 |
| 가능한 행동 | 6개 관절 각도의 범위 |
| 지금까지의 지각 | 카메라 영상과 관절값의 흐름 |

> **M6에서 가장 먼저 정할 것은 성능 척도입니다.** "잘 동작한다"가 아니라 "10회 중 7회 이상 성공, 1회당 20초 이내"처럼 **숫자** 로 정해야 합리적인 설계를 할 수 있습니다. 성능 척도는 **에이전트 바깥에서, 미리** 정합니다.

### 2-4. 합리적 ≠ 전지전능

합리적이라는 것은 **아는 범위 안에서 최선** 이라는 뜻이지, 모든 것을 안다는 뜻이 아닙니다. 카메라에 가려진 물체를 못 잡은 것은 비합리적인 것이 아니라 **지각의 한계** 입니다. 대신 합리적 에이전트는 **정보를 더 모으는 행동**(카메라 추가, 다시 보기)과 **경험으로 배우기**(데이터 추가)를 할 수 있어야 합니다.

## 3. PEAS — 프로젝트를 네 칸으로 정의하기

**PEAS** = **P**erformance measure(성능 척도) · **E**nvironment(환경) · **A**ctuators(액추에이터) · **S**ensors(센서)

어떤 에이전트를 만들기 전에 이 네 칸부터 채우면, 무엇을 만들지와 무엇을 재야 할지가 동시에 정해집니다.

### 예시 ① 물체 집어 옮기기 (★)

| | 내용 |
|---|---|
| **P** 성능 척도 | 10회 중 성공 횟수, 1회 소요 시간, 물체·작업대 충돌 0회 |
| **E** 환경 | 테이프로 표시한 작업대, 빨간 큐브, 상자, 교실 조명 |
| **A** 액추에이터 | SO-101 팔로워 서보 6개 |
| **S** 센서 | 전면 USB 카메라, 서보 위치 센서 |

### 예시 ② 불량품 골라내기 (★★)

| | 내용 |
|---|---|
| **P** 성능 척도 | 불량 검출률(Recall), 정상품을 잘못 치운 비율, 처리 시간, 리포트 정확도 |
| **E** 환경 | 검사대, 정상·불량 부품, 고정 조명 (M3 촬영 환경) |
| **A** 액추에이터 | SO-101(불량품 치우기), 화면·리포트 출력 |
| **S** 센서 | 검사용 카메라(Anomalib 입력), 로봇 카메라, 서보 위치 |

### 예시 ③ 말로 시키는 로봇 (★★★)

| | 내용 |
|---|---|
| **P** 성능 척도 | 지시를 올바르게 해석한 비율, 작업 성공률, 지시부터 완료까지 시간, 엉뚱한 동작 0회 |
| **E** 환경 | 작업대 위 여러 색의 블록, 사람의 음성 또는 텍스트 지시 |
| **A** 액추에이터 | SO-101, 화면 응답(LLM 답변) |
| **S** 센서 | 카메라(YOLO 입력), 키보드·마이크(지시 입력), 서보 위치 |

> 성능 척도는 M3에서 배운 **Precision·Recall**, M5에서 쓴 **성공률 표** 를 그대로 가져오면 됩니다. 발표 때 이 숫자를 보여 주는 것이 곧 "합리적 에이전트를 만들었다"는 증거입니다.

## 4. 환경 유형 — 로봇 세계는 왜 어려운가

### 4-1. 일곱 가지 기준

| 기준 | 쉬운 쪽 | 어려운 쪽 | SO-101 집기 작업 | 설계에 주는 의미 |
|---|---|---|---|---|
| 관측 | 완전 관측 | **부분 관측** | 부분 — 카메라 사각, 그리퍼에 가린 물체 | 지금 화면만으로 부족 → **내부 상태**(관절값, "이미 집었나")가 필요 |
| 에이전트 수 | **단일** | 다중 | 단일 (사람이 끼어들면 다중) | 사람 손이 들어오는 상황을 안전 규칙으로 처리 |
| 결정성 | 결정적 | **확률적** | 확률적 — 같은 명령에도 미끄러짐, 모터 오차 | 한 번에 성공한다고 가정하지 말고 **확인 후 재시도** |
| 에피소드성 | 에피소드형 | **순차형** | 시도와 시도 사이는 에피소드형, 한 시도 안은 **순차형** | 앞 행동이 다음 상태를 바꿈 → **오차 누적**(05a 참고) |
| 변화 | 정적 | **동적** | 동적 — 판단하는 사이에도 팔이 움직이고 물체가 밀림 | **추론 속도** 가 성능의 일부 → OpenVINO·디바이스 선택 |
| 값의 종류 | 이산 | **연속** | 연속 — 관절 각도, 픽셀 위치 | 분류가 아니라 **연속값 출력**(회귀) |
| 사전 지식 | 알려진 | **알려지지 않은** | 반쯤 알려짐 — 물리 법칙을 코드로 주지 않고 데이터로 배움 | 학습이 필요 |

> 교재의 분류표는 "부품 집기 로봇"을 **에피소드형** 으로 분류합니다. 부품 하나하나가 앞 부품과 독립이라는 뜻입니다. 하지만 **한 번 집는 동작 안** 에서는 30fps × 15초 = 450번의 결정이 이어지는 순차형 문제입니다. 어느 시간 단위로 보느냐에 따라 분류가 달라진다는 점이 좋은 토론거리입니다.

### 4-2. 비교해 보기

| 작업 환경 | 관측 | 결정성 | 에피소드성 | 변화 | 값 |
|---|---|---|---|---|---|
| M3 이미지 불량 검사 | 완전 | 결정적 | 에피소드형 | 정적에 가까움 | 연속 |
| M4 문서 질의응답(RAG) | 부분 | 확률적 | 순차형(대화) | 정적 | 이산(텍스트) |
| **M5 SO-101 집기** | **부분** | **확률적** | **순차형** | **동적** | **연속** |
| M6 말로 시키는 로봇 | 부분 | 확률적 | 순차형 | 동적 | 연속 + 이산 |

**같은 "AI"라도 로봇이 가장 어려운 칸에 몰려 있습니다.** 이미지 검사가 잘 되던 모델이 로봇에 붙으면 갑자기 어려워지는 이유가 여기에 있습니다.

## 5. 에이전트 구조 — 반사형부터 학습형까지

### 5-1. 다섯 가지 구조를 M6 시스템으로

| 구조 | 결정 방식 | M6 시스템 예 | 한계 |
|---|---|---|---|
| **단순 반사** | 지금 보이는 것 + if-then 규칙 | "YOLO가 빨간 큐브를 보면 → 집기 정책 실행" | 지금 화면에 안 보이는 정보는 못 씀 |
| **모델 기반 반사** (상태 있음) | 내부 상태 + 규칙 | "이미 3개 옮겼으면 멈춤", "그리퍼가 닫혀 있으면 놓기 단계" | 목표가 바뀌면 규칙을 다시 써야 함 |
| **목표 기반** | 목표를 이루는 행동 순서를 찾음 | LLM이 "빨간 것 다음 파란 것"을 계획하고 정책을 순서대로 호출 | "얼마나 좋은지"는 표현 못 함 |
| **효용 기반** | 여러 선택지를 점수로 비교 | 집을 후보가 여럿일 때 가장 가깝고 확신도 높은 것부터 | 점수 함수를 잘 설계해야 함 |
| **학습** | 위 구조 + 피드백으로 개선 | 성공률을 재고, 실패한 위치의 시연을 추가해 재학습 | 데이터·학습 시간 |

ACT 정책 자체는 지각을 받아 바로 동작을 내는 **반사형에 가까운 프로그램** 입니다(관절값이라는 상태를 함께 봄). M6에서는 그 **위에** 상태·목표·점수를 다루는 층을 얹는 것이 핵심입니다.

### 5-2. 학습 에이전트 — 우리가 13일차에 돌린 루프

| 학습 에이전트의 구성 요소 | 하는 일 | 우리 과정에서 |
|---|---|---|
| 수행 요소 | 지각을 받아 행동 선택 | 노트북에서 도는 ACT 정책 |
| 비평가 (Critic) | 고정된 성능 기준으로 잘했는지 피드백 | 13일차 **성공률 평가표** |
| 학습 요소 | 피드백으로 수행 요소를 개선 | 데이터 보강 후 **B70 재학습** |
| 문제 생성기 | 새로운 경험을 할 행동을 제안 | "표시 +2cm 위치에서도 시도해 보자" |

> 성능 기준(비평가의 기준)은 에이전트 **바깥에 고정** 해야 합니다. 결과를 보고 기준을 낮추면 학습이 아니라 자기 합리화가 됩니다. M6 기획서에 성공 기준을 **미리** 적는 이유입니다.

## 6. 판단 계층 — 규칙·학습·LLM 중 무엇으로

### 6-1. 지식 기반 에이전트 — 판단을 "아는 것 + 추론"으로 나누기

7장의 **지식 기반 에이전트** 는 판단을 두 부분으로 나눕니다.

| 구성 | 성격 | M6 예 |
|---|---|---|
| **지식 베이스(KB)** | 이 분야에 대한 사실과 규칙. 프로젝트마다 다름 | "불량이고 로봇이 대기 중이면 치운다", "손이 보이면 멈춘다" |
| **추론 엔진** | KB에서 결론을 끌어내는 방법. 분야와 무관 | if-then 평가 코드, (확장하면) 논리 추론기 |

그리고 두 가지 동작으로 씁니다.

- **TELL(알려 주기)**: 새로 알게 된 사실을 KB에 넣는다. → "YOLO: 빨간 큐브가 (x, y)에 있음", "Anomalib: 3번 부품 불량"
- **ASK(묻기)**: 지금 무엇을 해야 하는지 KB에 묻는다. → 답은 KB에서 **논리적으로 따라 나와야** 한다.

**선언적(declarative) 방식** 의 장점은, 추론 코드는 그대로 두고 **규칙(KB)만 바꿔서** 다른 작업에 쓸 수 있다는 것입니다.

### 6-2. 명제 논리로 판단 규칙 쓰기

"불량품 골라내기" 프로젝트의 판단을 명제로 쓰면 이렇습니다.

| 기호 | 의미 (인식 계층이 TELL) |
|---|---|
| `D` | 검사 중인 부품이 불량이다 (Anomalib 점수 > 임계값) |
| `R` | 로봇이 대기 상태다 |
| `H` | 작업대에 사람 손이 보인다 (YOLO person/hand) |
| `Act_치우기` | "치우기" 정책을 실행한다 |
| `Act_정지` | 로봇을 정지한다 |

```text
규칙 1 (안전):  H ⇒ Act_정지
규칙 2 (작업):  D ∧ R ∧ ¬H ⇒ Act_치우기
규칙 3 (대기):  ¬D ⇒ ¬Act_치우기
```

파이썬으로 옮기면 그대로 판단 계층이 됩니다.

```python
def decide(defect: bool, robot_idle: bool, hand_visible: bool) -> str:
    if hand_visible:                  # 규칙 1 — 안전이 항상 먼저
        return "stop"
    if defect and robot_idle:         # 규칙 2
        return "run_policy:remove_defect"
    return "wait"                     # 규칙 3
```

### 6-3. 웜푸스 세계에서 배우는 것 — 보이지 않아도 안전을 추론한다

웜푸스 세계의 에이전트는 구덩이를 직접 보지 못하지만, "바람이 안 분다 → 옆 칸에 구덩이가 없다"처럼 **부분 관측에서도 확실히 안전한 것만 골라** 움직입니다.

로봇에 옮기면 **안전 규칙** 이 됩니다. 학습된 정책은 "대체로" 잘하지만 **보장** 은 못 합니다. 반면 규칙은 KB에서 따라 나오는 결론이 **항상 참** 이 되도록(건전하게) 만들 수 있습니다. 그래서 현장 시스템은

> **학습된 정책이 행동을 제안하고, 규칙이 그 행동을 허락하거나 막는다.**

는 구조를 씁니다. 손이 보이면 멈춘다, 관절이 범위를 벗어나면 멈춘다, 정해진 시간이 지나면 멈춘다 — M6 시스템에는 이런 규칙을 **최소 하나** 넣으세요.

### 6-4. 세 가지 방식 비교

| | 규칙 기반 (지식 기반) | 학습 기반 | LLM 기반 (M4 에이전트) |
|---|---|---|---|
| 판단 근거 | 사람이 쓴 규칙 | 데이터에서 배운 패턴 | 언어 모델의 해석 + 도구 호출 |
| 강점 | 설명 가능, 검증 가능, 빠름, 안전 규칙에 적합 | 규칙으로 쓰기 어려운 판단(영상 속 미묘한 차이) | 자연어 지시, 유연한 계획 |
| 약점 | 상황이 많아지면 규칙 폭발, 예외에 약함 | 데이터 필요, 왜 그렇게 판단했는지 설명 어려움 | 느림, 가끔 엉뚱한 해석, 결과 보장 없음 |
| 어울리는 M6 주제 | ★ 물체 옮기기, ★★ 불량품 골라내기 | (인식 계층에서 이미 사용) | ★★★ 말로 시키는 로봇, 검사 리포트 |
| 엣지 부담 | 거의 없음 | 모델 크기에 따라 | 큼 (INT4 소형 모델 권장) |

**권장 조합**: 판단의 뼈대와 안전은 **규칙**, 사람과의 인터페이스는 **LLM**, 보고 움직이는 것은 **학습된 모델**. LLM을 쓰더라도 도구는 3–4개로 제한하고(M4), 안전 규칙은 LLM보다 **바깥쪽** 에 둡니다.
