# 05a. 데이터 수집 이론 — 모방학습 데이터는 왜, 어떻게 모아야 하나

> [05 데이터 수집](05-data-collection.md)이 "어떻게 녹화하나"라면, 이 문서는 "**왜** 그렇게 녹화해야 하나"를 다룹니다.
> 13일차 녹화 전 이론 시간, 그리고 B70 학습을 기다리는 시간에 사용합니다.

## 학습 목표

- 모방학습이 지도학습과 같은 구조이면서도 **데이터에 훨씬 민감한 이유**(분포 이동, 오차 누적)를 설명할 수 있다.
- 시연 데이터를 이루는 관측·행동·시간 정보가 각각 무엇이고, 어떻게 맞물려 저장되는지 안다.
- 좋은 데이터의 다섯 가지 조건(일관성, 커버리지, 시작 상태, 시간 품질, 장면 고정)을 이유와 함께 말할 수 있다.
- 여러 사람의 데이터를 합칠 때의 장단점과, 그래서 녹화 프로토콜이 필요한 이유를 이해한다.
- 에피소드 품질을 숫자로 점검하는 방법을 안다.

## 1. 모방학습 = 지도학습, 그런데 왜 더 어려운가

### 1-1. 구조는 M3와 같다

| | M3 YOLO (지도학습) | M5 ACT (모방학습, Behavior Cloning) |
|---|---|---|
| 입력 x | 이미지 | 카메라 이미지 + 팔로워 관절값 |
| 정답 y | 박스와 클래스 (사람이 라벨링) | 리더 관절값 (사람이 **시연** 으로 라벨링) |
| 학습 | 예측과 정답의 차이를 줄인다 | 예측 동작과 사람 동작의 차이(L1)를 줄인다 |
| 라벨링 방법 | Roboflow에서 박스 그리기 | 리더 팔을 움직이는 것 자체가 라벨링 |

텔레오퍼레이션은 결국 **"이 장면에서는 이렇게 움직여라"라는 라벨을 실시간으로 다는 작업** 입니다. 라벨의 품질이 곧 모델의 품질입니다.

### 1-2. 결정적 차이 — 모델이 자기 다음 입력을 만든다

YOLO는 틀려도 다음 이미지는 그대로 들어옵니다. 하지만 로봇 정책은 **자기가 움직인 결과가 다음 관측** 이 됩니다.

```text
학습 데이터:  사람이 만든 궤적만 봄   ──── 늘 "좋은 상태"만 봄
실제 실행:    정책이 조금 틀림 → 처음 보는 자세 → 더 틀림 → 더 낯선 자세 → …
```

이것을 **분포 이동(distribution shift)**, 특히 **공변량 이동(covariate shift)** 이라고 부릅니다. 학습 때 본 입력 분포(사람의 궤적)와 실행 때 만나는 입력 분포(정책 자신의 궤적)가 달라지는 현상입니다.

### 1-3. 오차 누적 (compounding error)

Ross, Gordon, Bagnell(2011)은 단순 모방학습(Behavior Cloning)에서 한 스텝 오차율이 ε일 때, 길이 T인 작업 전체의 오차가 **최악의 경우 T²ε에 비례해** 커질 수 있음을 보였습니다. 한 번 벗어나면 그 뒤 스텝이 모두 낯선 상태에서 진행되기 때문입니다.

| 작업 길이 | 스텝 오차 1%일 때 직관 |
|---|---|
| 짧은 작업 (수십 스텝) | 거의 문제없음 |
| 긴 작업 (수백 스텝) | 중간에 한 번 벗어나면 끝까지 회복 못 할 수 있음 |

30fps로 15초 녹화하면 **450스텝** 입니다. 짧아 보여도 충분히 긴 작업입니다.

### 1-4. 그래서 나온 해법들

| 해법 | 아이디어 | 데이터 수집과의 관계 |
|---|---|---|
| **Action Chunking** (ACT) | 수십 스텝을 한 번에 예측해 "결정 횟수" 자체를 줄인다 | 일관된 시연일수록 묶음 예측이 잘 맞음 |
| **DAgger** (Ross et al., 2011) | 정책이 실행하다 벗어난 상태에서 사람이 올바른 동작을 다시 라벨링해 데이터에 추가 | **복귀(recovery) 시연** 의 가치를 보여 줌 |
| **데이터 다양화** | 시작 위치·물체 위치를 조금씩 바꿔 "벗어난 상태"도 미리 보여 줌 | 우리 수업의 "표시 안에서 1–2cm씩 바꾸기" |

> **핵심 메시지**: 모방학습에서 데이터는 "많을수록 좋다"가 아니라 **정책이 실행 중에 만날 상태를 얼마나 미리 보여 줬느냐** 가 중요합니다.

## 2. 시연 데이터는 무엇으로 이루어지나

### 2-1. 한 프레임의 구성

| 구분 | LeRobot 키 | SO-101에서 | 의미 |
|---|---|---|---|
| 관측 — 상태 | `observation.state` | 팔로워 관절 6개 (float) | 로봇이 지금 어떤 자세인가 |
| 관측 — 영상 | `observation.images.front` | 640×480 RGB | 세상이 지금 어떤가 |
| 행동 | `action` | 리더 관절 6개 (float) | 사람이 지금 무엇을 시켰나 |
| 시간 | `timestamp`, `frame_index` | 1/30초 간격 | 언제의 데이터인가 |
| 구분 | `episode_index`, `task_index` | 0, 1, 2 … | 몇 번째 시연, 어떤 작업인가 |

### 2-2. 왜 action은 팔로워가 아니라 리더 값인가

- 팔로워 값(`observation.state`)은 "결과"이고, 리더 값(`action`)은 "의도"입니다.
- 팔로워는 모터 속도·부하 때문에 리더를 **조금 늦게** 따라갑니다. 물체를 쥘 때는 그리퍼가 물체에 막혀 리더만큼 닫히지 못합니다.
- 정책이 배워야 하는 것은 "어떤 명령을 내려야 하는가"이므로 **명령 = 리더 값** 이 정답입니다.

> 경험자 실습: `action - observation.state`를 그려 보면, 빠르게 움직인 구간과 물체를 쥔 구간에서 차이가 커집니다. 이것이 추종 오차이자, 그리퍼 쥐는 힘이 데이터에 담기는 방식입니다.

### 2-3. 행동 공간(action space)의 종류

| 방식 | 내용 | 장단점 |
|---|---|---|
| **절대 관절 위치** (우리 수업) | 관절 6개의 목표 각도 | 단순, 리더-팔로워 구조와 딱 맞음. 캘리브레이션에 민감 |
| 관절 위치 변화량 (delta) | 지금보다 얼마나 더 움직일지 | 시작 자세 차이에 덜 민감, 오차가 적분되며 누적될 수 있음 |
| 엔드이펙터 좌표 | 그리퍼 끝의 x, y, z, 회전 | 로봇이 달라도 옮기기 쉬움, 역기구학 계산 필요 |

**절대 관절 위치** 는 "모터 숫자 → 각도" 변환에 전적으로 의존합니다. 그래서 어제 캘리브레이션을 그렇게 강조한 것입니다. 캘리브레이션이 틀린 팔로 모은 데이터는 **라벨 자체가 틀린 데이터** 입니다.

### 2-4. 시간 — fps와 동기화

- 모든 센서가 **같은 시각의 값** 으로 한 행에 묶여야 합니다. 카메라는 30fps로 프레임을 주고, 모터는 시리얼 통신으로 값을 읽습니다. 이 둘의 시각을 맞추는 것이 녹화 프로그램의 일입니다.
- 노트북이 바쁘면(다른 프로그램, 브라우저 탭 다수) 프레임이 밀리거나 빠집니다. **녹화 중에는 다른 무거운 작업을 하지 않습니다.**
- fps를 바꾸면 "한 스텝 = 몇 초"가 바뀌어 ACT의 묶음 길이(chunk)가 의미하는 시간도 바뀝니다. **반 전체 fps 통일** 이 병합 조건인 이유입니다.

## 3. 좋은 데이터의 다섯 가지 조건

### 조건 ① 일관성 — 같은 상황에서는 같은 행동

모델은 같은 입력에 대해 정답들의 **평균** 을 배우려는 경향이 있습니다.

```text
상황: 컵이 정면에 있음
  시연 A: 왼쪽으로 돌아서 잡음
  시연 B: 오른쪽으로 돌아서 잡음
  단순 평균: 정면으로 돌진 → 컵을 침  ❌
```

이것을 **다봉성(multimodality) 문제** 라고 합니다. 정답이 여러 개(봉우리가 여러 개)인데 평균은 어느 봉우리에도 속하지 않습니다.

- ACT의 CVAE, Diffusion Policy(Chi et al., 2023) 같은 구조는 이 문제를 완화하려고 만들어졌습니다.
- 하지만 **가장 확실한 해결은 데이터 단계에서 전략을 통일** 하는 것입니다. → "항상 위에서 내려와 잡는다", "항상 오른쪽으로 옮긴다"처럼 반 전체 규칙을 정합니다.

### 조건 ② 커버리지 — 실행 중 만날 상태를 미리 보여 주기

| 너무 좁으면 | 적당하면 | 너무 넓으면 |
|---|---|---|
| 물체가 항상 같은 점 → 위치를 **외움** | 표시 안에서 1–2cm씩 변화 → 물체를 **보고** 찾아감 | 범위가 넓은데 에피소드가 적음 → 각 위치의 예시가 부족 |

**데이터 수와 다양성은 함께 늘려야 합니다.** 위치 변화를 크게 주고 싶다면 그만큼 에피소드도 늘려야 합니다.

### 조건 ③ 시작 상태 — 첫 프레임이 같아야 하는 이유

- 추론을 시작하는 순간의 자세가 학습 데이터의 시작 자세와 다르면, 정책은 **첫 스텝부터 분포 밖** 에서 출발합니다(1-2의 분포 이동).
- 그래서 모든 에피소드를 같은 "홈 자세"에서 시작하고, 추론도 같은 자세에서 시작합니다.
- 끝 자세도 통일하면 정책이 "작업이 끝났다"를 배우기 쉬워집니다.

### 조건 ④ 시간 품질 — 멈칫, 정지, 속도

| 현상 | 데이터에 남는 것 | 정책이 배우는 것 |
|---|---|---|
| 중간에 멈칫 | 같은 장면에서 행동이 "정지" | 비슷한 장면에서 **멈춰 버림** |
| 녹화 시작 후 한참 대기 | 앞부분에 정지 프레임 다수 | 시작하자마자 가만히 있음 |
| 시연마다 속도가 크게 다름 | 같은 장면에 다른 속도 | 속도가 들쭉날쭉, 평균화 |
| 너무 빠른 시연 | 팔로워 추종 오차 증가, 영상 흐림 | 정확도 하락 |

→ **"일정하고 약간 느긋한 속도로, 망설임 없이"** 가 정답입니다. 시작 버튼을 누르면 바로 움직이고, 끝나면 바로 정지합니다.

### 조건 ⑤ 장면 고정 — 카메라·조명·배경

정책의 입력 대부분은 **영상** 입니다. 영상이 바뀌면 입력 분포가 바뀝니다(M3에서 배운 도메인 변화와 같은 문제).

| 바뀌는 것 | 영향 |
|---|---|
| 카메라 위치·각도 | 같은 물체가 화면의 다른 픽셀에 → 위치 판단이 어긋남. **가장 치명적** |
| 조명 (창가 햇빛, 시간대) | 밝기·그림자 변화 → 물체 인식 불안정 |
| 배경 (사람, 가방, 컵) | 모델이 엉뚱한 물체를 단서로 학습 |
| 손·몸이 화면에 들어옴 | 추론 때는 손이 없음 → 학습과 실행의 장면이 다름 |

> 그래서 어제 **테이프로 카메라 위치를 표시** 했습니다. 녹화 중 카메라를 건드렸다면 표시에 맞춰 되돌리고, 그 직전 에피소드는 다시 확인합니다.

## 4. 성공한 시연만 모아야 할까? — 실패와 복귀

| 종류 | 넣을까? | 이유 |
|---|---|---|
| 깨끗한 성공 시연 | ✅ 기본 | 정책이 따라 할 모범 |
| 실패한 시연 (물체 떨어뜨림, 엉뚱한 곳) | ❌ 삭제 | 모방학습은 "좋고 나쁨"을 구분하지 않고 **그대로 따라 함** |
| **복귀 시연** (살짝 헛집은 뒤 바로 다시 잡아 성공) | △ 소량은 도움 | 벗어난 상태에서 돌아오는 법을 보여 줌 (DAgger의 아이디어) |

- 오늘 수업에서는 **깨끗한 성공 시연** 만 모읍니다. 반 전체 데이터를 합치기 때문에 기준을 단순하게 유지하는 편이 안전합니다.
- 경험자 조가 개인 데이터셋을 따로 만든다면, 10개 중 1–2개 정도 복귀 시연을 넣어 보고 성능 차이를 비교해 볼 만합니다.

## 5. 얼마나 모아야 하나

| 근거 | 내용 |
|---|---|
| ACT 논문 (Zhao et al., 2023) | 실물 양팔 작업에서 **약 10분 분량의 시연** 으로 80–90% 성공률을 보고 |
| Physical AI Studio 문서 | 학습 전 **최소 50 에피소드** 권장 |
| 우리 수업 | 1인 10개 × 반 전체 → 50개 이상을 협업으로 확보 |

계산해 보면 15초 × 50개 = 약 12분 분량으로, 논문의 규모와 비슷합니다.

**늘리기 전에 먼저 확인할 것**: 성능이 낮을 때 무조건 더 모으기보다, 아래 순서로 원인을 좁히는 편이 빠릅니다.

1. 불량 에피소드가 섞였나? → 삭제
2. 장면(카메라·조명)이 녹화 때와 같은가? → 복원
3. 시작 자세가 같은가? → 맞춤
4. 그래도 특정 위치에서만 실패하나? → **그 위치의 에피소드를 추가**

## 6. 여러 사람의 데이터를 합친다는 것

### 6-1. 장점과 단점

| 장점 | 단점 |
|---|---|
| 혼자서는 어려운 50+ 에피소드를 빠르게 확보 | 사람마다 속도·경로·잡는 방식이 다름 (다봉성 ↑) |
| 시연 스타일이 다양해져 일반화에 도움될 수 있음 | 조마다 카메라·조명이 조금씩 다름 (분포 ↑) |
| 실제 산업 현장 방식과 같음 (여러 작업자, 여러 라인) | 한 명의 불량 데이터가 전체에 영향 |

### 6-2. 그래서 필요한 것 — 녹화 프로토콜

산업 현장에서 여러 작업자가 데이터를 모을 때는 **프로토콜(작업 표준서)** 을 먼저 정합니다. 우리 반의 프로토콜:

| 항목 | 우리 반 기준 | 지키지 않으면 |
|---|---|---|
| 작업 문구 | 칠판 문장 그대로 | 데이터가 여러 작업으로 쪼개짐 |
| 카메라 이름·해상도·fps | front · 640×480 · 30 | 병합 실패 |
| 시작·끝 자세 | 홈 자세 | 첫 스텝부터 분포 밖 |
| 잡는 전략 | 예: 위에서 내려와 잡기 | 다봉성 → 평균 동작 |
| 물체 위치 | 표시 안에서 1–2cm 변화 | 위치 암기 또는 예시 부족 |
| 속도 | 일정하고 약간 느긋하게 | 멈춤·속도 평균화 |
| 실패 처리 | Discard 후 재녹화 | 실패를 모방 |

### 6-3. 정규화 통계가 왜 그렇게 중요한가

ACT는 학습 전에 관절값과 이미지를 **평균 0, 표준편차 1 근처로 맞추는 정규화** 를 합니다. 그 평균과 표준편차가 `meta/stats.json`에 저장됩니다.

- 학생 10명의 데이터를 합쳤는데 통계를 1명 기준으로 쓰면, 나머지 9명의 데이터는 엉뚱한 범위로 변환됩니다.
- 이 오류는 **에러 메시지 없이 성능만 떨어뜨립니다**. 그래서 병합 명령으로 통계를 반드시 다시 계산합니다.
- 같은 이유로, 캘리브레이션이 틀린 팔 하나가 섞이면 통계 자체가 흔들립니다.

## 7. 데이터를 검증하는 법 — 에피소드 단위로 생각하기

### 7-1. 학습/검증 분할은 프레임이 아니라 에피소드 단위

한 에피소드 안의 프레임들은 1/30초 간격이라 **거의 똑같습니다**. 프레임을 무작위로 섞어 학습/검증으로 나누면, 검증 프레임의 바로 옆 프레임이 학습에 들어가 있어 점수가 비현실적으로 좋게 나옵니다. 이것이 **데이터 누수(data leakage)** 입니다.

→ 성능을 제대로 보려면 **에피소드 전체를 통째로** 학습 또는 검증에 넣어야 합니다. 더 엄격하게는 "한 학생의 데이터 전체를 빼고 학습 → 그 학생 데이터로 검증"처럼 사람 단위로 나눌 수도 있습니다.

### 7-2. 숫자로 보는 에피소드 품질

눈으로 재생해 보는 것과 함께, 아래 지표를 숫자로 보면 불량 에피소드가 바로 드러납니다.

| 지표 | 계산 | 의심 신호 |
|---|---|---|
| 에피소드 길이 | 프레임 수 ÷ fps | 다른 에피소드보다 유난히 길거나 짧음 |
| 시작 자세 편차 | 첫 프레임 관절값과 전체 평균의 차이 | 혼자 크게 다름 → 시작 자세 불일치 |
| 정지 비율 | 관절 변화가 거의 없는 프레임 비율 | 높음 → 멈칫·대기 구간이 많음 |
| 추종 오차 | `action`과 `observation.state` 차이의 평균 | 큼 → 너무 빠른 시연 또는 통신·캘리브레이션 문제 |

이 저장소의 [`scripts/analyze_episodes.py`](../scripts/analyze_episodes.py)가 위 네 가지를 계산해 표로 보여 줍니다.

```bash
python3 scripts/analyze_episodes.py ~/peek/s05_pick
```

> pandas와 pyarrow가 필요합니다 (`pip install pandas pyarrow`). Export한 zip을 푼 폴더를 지정합니다.

## 9. 자기점검

1. 모방학습이 지도학습과 같은 구조인데도 데이터에 더 민감한 이유를 "분포 이동"이라는 말을 넣어 설명해 보세요.
2. 시연 A는 왼쪽으로, 시연 B는 오른쪽으로 돌아서 물체를 잡았습니다. 이 데이터로 학습한 정책은 어떻게 움직일 수 있고, 데이터 단계에서 어떻게 막을 수 있나요?
3. `action`에 팔로워가 아니라 리더 관절값을 쓰는 이유는?
4. 물체를 항상 정확히 같은 위치에 두고 녹화하면 어떤 문제가 생기나요?
5. 실패한 시연은 왜 지워야 하고, 복귀 시연은 왜 일부 도움이 될 수 있나요?
6. 프레임 단위로 학습/검증을 나누면 왜 점수가 부풀려지나요?
7. 병합 후 `stats.json`을 다시 계산하지 않으면 어떤 일이 생기나요?

<details>
<summary>모범 답안</summary>

1. 학습 데이터는 사람이 만든 "좋은 궤적"만 담고 있지만, 실행 중에는 정책 자신이 만든 궤적을 입력으로 받습니다. 정책이 조금 틀리면 학습 때 본 적 없는 상태로 들어가고(분포 이동), 거기서 더 틀려 오차가 누적됩니다.
2. 두 방식의 평균인 "정면으로 돌진"처럼 어느 시연에도 없는 동작을 할 수 있습니다(다봉성 문제). 녹화 전에 잡는 전략을 하나로 통일하면 막을 수 있습니다.
3. 정책이 배워야 하는 것은 로봇에 내릴 "명령"입니다. 팔로워 값은 명령의 결과이고 지연과 막힘(그리퍼가 물체에 막힘 등)이 섞여 있습니다.
4. 정책이 물체를 보고 찾아가는 대신 위치를 외웁니다. 추론 때 물체가 조금만 벗어나도 실패합니다.
5. 모방학습은 성공과 실패를 구분하지 않고 따라 하기 때문에 실패 동작도 배웁니다. 복귀 시연은 벗어난 상태에서 돌아오는 법을 보여 주어 오차 누적을 줄여 줄 수 있습니다(DAgger의 아이디어).
6. 같은 에피소드의 이웃 프레임은 거의 같아서, 검증 프레임과 거의 같은 프레임이 학습에 들어갑니다(데이터 누수).
7. 일부 학생의 데이터가 잘못된 범위로 정규화되어, 에러 없이 성능만 떨어집니다.

</details>

## 용어 사전

| 용어 | 뜻 |
|---|---|
| 모방학습 (Imitation Learning) | 사람의 시연을 따라 하도록 정책을 학습하는 방법 |
| Behavior Cloning (BC) | 관측 → 행동을 지도학습으로 바로 배우는 가장 단순한 모방학습 |
| 에피소드 (episode) | 시작부터 끝까지 한 번의 시연 |
| 관측 (observation) | 정책의 입력. 카메라 영상 + 로봇 상태 |
| 행동 (action) | 정책의 출력. 우리 수업에서는 6개 관절의 목표 위치 |
| 분포 이동 / 공변량 이동 | 학습 때와 실행 때의 입력 분포가 달라지는 현상 |
| 오차 누적 (compounding error) | 작은 오차가 다음 상태를 바꾸며 점점 커지는 현상 |
| 다봉성 (multimodality) | 같은 상황에 올바른 행동이 여러 개 있는 성질. 평균을 내면 틀린 행동이 됨 |
| DAgger | 정책이 벗어난 상태에서 사람이 다시 라벨링해 데이터를 보강하는 방법 |
| Action Chunking | 여러 스텝의 행동을 한 번에 예측하는 방법 (ACT의 핵심) |
| 정규화 통계 (stats) | 데이터를 비슷한 범위로 맞추기 위한 평균·표준편차 |
| 데이터 누수 (data leakage) | 검증 데이터의 정보가 학습에 섞여 성능이 부풀려지는 현상 |
| 텔레오퍼레이션 | 사람이 원격으로 로봇을 조종하는 것. 리더-팔로워 방식 |
