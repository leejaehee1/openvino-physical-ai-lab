# 수강생 수준 진단

> 강사용. 오늘 오전은 출석과 로봇 세팅으로 시간이 빠듯하므로 **따로 시험 시간을 잡지 않고**, 수업 흐름 안에 끼워 넣는 방식으로 구성했습니다.

| 언제 | 방법 | 시간 | 알 수 있는 것 |
|---|---|---|---|
| 수업 전 | 이전 강사·KOSA 담당자에게 확인 | — | 과제 제출 현황, 온라인 구간 출석·질문이 많던 사람 |
| 강사 소개 직후 | 1. 손들기 5문항 | 2분 | 경험 수준 (조 편성용) |
| 개관 끝 | 2. 개념 확인 퀴즈 8문항 | 5–8분 | M2–M4를 실제로 이해했는지 |
| 설치 실습 중 | 3. 관찰 체크 | 0분 (돌아다니며) | 터미널·문제 해결 능력 |
| 하루 끝 | 4. 퇴실 질문 3개 | 3분 | 오늘 내용 이해도, 내일 보충할 것 |

## 0. 수업 전 — 기존 기록 확인

- 이전 강사님이 교안을 공유해 주실 때 **"과제를 끝까지 한 사람 / 막혔던 사람"** 을 함께 여쭤봅니다.
- 중간 과정이 온라인이었으므로 LMS에 **실습 과제 제출 기록**이 있으면 KOSA 담당자분께 요청합니다 (오전 출석 체크 때).
- 특히 M3(YOLO·Anomalib 학습)와 M4(로컬 LLM·에이전트)를 끝까지 돌려 봤는지가 M5·M6 진행 속도를 좌우합니다.

## 1. 손들기 5문항 (2분)

스스로 판단하게 해서 부담 없이 진행합니다. "해 봤다"만 손들기.

1. 리눅스 터미널에서 `cd`, `ls`, `sudo apt install`을 **도움 없이** 쓸 수 있다 (M0)
2. 남이 쓴 Python 코드를 열어 **어디를 고치면 되는지** 찾을 수 있다 (M1)
3. OpenVINO로 모델을 불러와 **CPU·GPU·NPU를 바꿔 가며** 실행해 봤다 (M2)
4. YOLO나 Anomalib으로 **내 데이터로 모델을 직접 학습**해 봤다 (M3)
5. 노트북에서 **로컬 LLM을 띄우거나 RAG·에이전트**를 끝까지 돌려 봤다 (M4)

+ 보너스: Docker를 써 본 적이 있다 / 로봇이나 아두이노를 다뤄 본 적이 있다

손 든 수를 메모해 두고, **많이 든 사람(4–5개)과 적게 든 사람(0–2개)을 짝지어** 로봇 조를 편성합니다.

## 2. 개념 확인 퀴즈 (5–8분)

손들기는 자기 평가라 실제보다 높게 나옵니다. 아래 문항으로 **진짜 이해했는지** 확인합니다.
Kahoot, Google Forms, Slido 중 편한 도구에 넣거나, 시간이 없으면 칠판에 써 두고 손들기로 답하게 합니다.
각 문항은 **M5·M6에서 바로 다시 쓰는 개념**만 골랐습니다.

| # | 모듈 | 문항 | M5·M6에서 다시 쓰는 곳 |
|:---:|---|---|---|
| 1 | M2 | 학습(Training)과 추론(Inference)의 차이를 한 문장으로 말하면? | B70은 학습, 노트북은 추론 |
| 2 | M2 | OpenVINO IR 모델은 어떤 두 파일로 이루어지나? | runtime export의 `exports/openvino` 폴더 |
| 3 | M2 | 같은 모델을 CPU·GPU·NPU에서 돌렸을 때 결과는 같고 다른 것은? | 디바이스별 정책 추론 비교 |
| 4 | M2 | INT8 양자화를 하면 무엇을 얻고 무엇을 잃을 수 있나? | 엣지 배포 판단 |
| 5 | M3 | 학습 데이터에 없던 조명·배경에서 모델 성능이 떨어지는 이유는? | 작업대·카메라 배치 고정 |
| 6 | M3 | Anomalib은 왜 **정상 데이터만으로** 학습하나? | M6 불량품 골라내기 주제 |
| 7 | M4 | RAG에서 "임베딩"은 무슨 역할을 하나? | M6 검사 기준 조회 |
| 8 | M4 | 에이전트의 "도구 호출(tool calling)"이란? 소형 모델에서 도구 수를 줄이는 이유는? | M6 LLM이 로봇 정책을 도구로 호출 |

<details>
<summary>모범 답안</summary>

1. 학습은 데이터로 모델의 가중치를 만드는 과정이고, 추론은 만들어진 모델에 새 입력을 넣어 결과를 얻는 과정. 학습은 무겁고(GPU 서버), 추론은 가벼워 현장 기기에서 한다.
2. `.xml`(네트워크 구조) + `.bin`(가중치).
3. 결과(예측)는 거의 같고, 속도·전력·첫 실행 시 컴파일 시간이 다르다. (정밀도 차이로 미세한 수치 차이는 있을 수 있음)
4. 얻는 것: 모델 크기 감소, 추론 속도 향상. 잃을 수 있는 것: 정확도 소폭 하락.
5. 모델은 학습 때 본 분포만 안다. 분포가 바뀌면(도메인 변화) 일반화가 안 된다. → 로봇 녹화 때 배치·조명을 고정하는 이유.
6. 불량은 드물고 종류가 다양해서 충분히 모으기 어렵다. 정상의 패턴을 배우고, 거기서 벗어나면 이상으로 판정한다.
7. 문장을 의미를 담은 숫자 벡터로 바꿔서, 질문과 의미가 가까운 문서를 벡터 검색으로 찾게 해 준다.
8. LLM이 직접 답하는 대신 "이 함수를 이 인자로 실행하라"는 구조화된 요청을 출력하고, 프로그램이 그 함수를 실행해 결과를 돌려주는 방식. 소형 모델은 선택지가 많으면 잘못된 도구나 인자를 고르기 쉬워서 3–4개로 제한한다.

</details>

## 3. 관찰 체크 — 설치 실습 중 돌아다니며

Docker 설치와 Studio 실행은 **시험보다 정확한 진단**입니다. 명단에 표시만 해 둡니다.

| 관찰 | 의미 |
|---|---|
| 명령어를 그대로 붙여넣고 에러 메시지를 읽지 않고 손을 든다 | 터미널·에러 해독이 약함 (M0·M1) → 짝꿍 배치, 명령어 카드 제공 |
| 에러 메시지를 검색하거나 AI 도구에 붙여넣어 스스로 해결한다 | M1의 "에러와 AI 활용" 목표 달성 |
| 먼저 끝내고 옆 사람을 돕는다 | 도우미로 지정 |
| `sudo`, 그룹 권한, 재로그인 개념을 묻지 않고 처리한다 | 리눅스 숙련 |

## 4. 퇴실 질문 (하루 끝, 3분)

포스트잇이나 설문으로 이름 없이 받습니다.

1. 오늘 배운 것 중 **옆 사람에게 설명할 수 있는 것** 하나는?
2. 아직 **헷갈리는 것** 하나는?
3. 오늘 진도 속도는? (빠름 / 적당 / 느림)

2번 답을 모아 13일차 시작 10분에 **자주 나온 질문 2–3개를 먼저 짚고** 시작합니다.
