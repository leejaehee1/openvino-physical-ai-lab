# 03. SO-ARM101 로봇 세팅 (91–92차시)

## 학습 목표

- SO-ARM101의 관절 구조와 리더·팔로워의 차이를 설명할 수 있다.
- 서보 모터 ID를 왜 설정하는지 이해하고, Studio 마법사로 설정한다.
- 캘리브레이션을 수행하고, 왜 팔마다 따로 해야 하는지 설명할 수 있다.

## 1. SO-ARM101 구조

6자유도(관절 5개 + 그리퍼) 오픈소스 로봇 팔입니다. 관절마다 Feetech **STS3215** 서보 모터가 하나씩 들어 있고, 모터들은 3핀 케이블로 ** 데이지 체인(줄줄이)** 연결되어 컨트롤 보드 하나로 제어됩니다.

| 모터 ID | 관절 이름 (LeRobot) | 움직임 |
|:---:|---|---|
| 1 | `shoulder_pan` | 베이스 좌우 회전 |
| 2 | `shoulder_lift` | 어깨 들기 |
| 3 | `elbow_flex` | 팔꿈치 굽히기 |
| 4 | `wrist_flex` | 손목 굽히기 |
| 5 | `wrist_roll` | 손목 돌리기 |
| 6 | `gripper` | 집게 열고 닫기 |

### 리더와 팔로워는 왜 모터가 다른가

| | 팔로워 (Follower) | 리더 (Leader) |
|---|---|---|
| 역할 | 실제로 작업하는 팔 | 사람이 손으로 잡고 움직이는 조종기 |
| 기어비 | 6개 모두 1/345 (힘이 셈) | 관절별로 1/191 · 1/345 · 1/147 혼합 |
| 이유 | 물체를 들 힘이 필요 | **사람 손으로 가볍게 움직이면서도 자기 무게는 버텨야** 함 |
| 끝부분 | 그리퍼 | 손잡이 + 트리거 |

리더 관절별 기어비: 1번 1/191 · 2번 1/345 · 3번 1/191 · 4·5·6번 1/147 (LeRobot 공식 문서 기준)

> 키트 조립 시 리더 모터가 섞이면 리더가 너무 뻑뻑하거나 축 처집니다. 모터 스티커의 기어비를 확인하세요.

### 컨트롤 보드와 전원

- 팔마다 **USB 1개(PC 통신) + 전원 어댑터 1개** 가 필요합니다. 리더·팔로워 합쳐 USB 2개.
- Waveshare 보드를 쓰는 경우 점퍼 2개가 **B 채널(USB)** 쪽에 있어야 합니다.
- 리눅스에서는 보드가 `/dev/ttyACM0`, `/dev/ttyACM1` 같은 이름으로 보입니다.

## 2. 배선과 연결 확인

1. 팔로워·리더 보드에 전원 어댑터 연결
2. 두 보드를 USB로 노트북에 연결
3. 카메라 USB 연결
4. 터미널에서 확인

```bash
ls /dev/ttyACM* /dev/video*
```

`/dev/ttyACM0 /dev/ttyACM1`(로봇 2대)과 `/dev/video0 …`(카메라)이 보이면 정상입니다.

어느 쪽이 리더인지 헷갈리면 **하나를 뽑았다 꽂으면서** 사라지는 이름을 확인합니다. 라벨 테이프로 "L" / "F"를 붙여 두세요.

5. 이제 Studio를 켭니다 (USB 먼저, Studio 나중).

```bash
cd ~/physical-ai-studio/application/docker
docker compose down
docker compose up -d
```

## 3. Studio에서 로봇 등록 — 모터 ID 설정과 캘리브레이션

<http://localhost:7860> → 프로젝트 생성(강사가 정한 이름, 예: `class_pick`) → **Robots(로봇)** 메뉴

### 3-1. 팔로워 추가

1. Add robot(로봇 추가) → 종류 **SO101 Follower** 선택
2. 시리얼 포트 선택 (2단계에서 확인한 팔로워 포트)
3. 이름 입력: `follower_<조번호>` (예: `follower_03`)
4. 설정 마법사가 열립니다.

### 3-2. 모터 ID 설정 (새 키트일 때만)

새 모터는 **모두 ID가 1** 로 출고됩니다. 한 줄에 같은 번호가 여러 개면 보드가 누구에게 명령하는지 구분할 수 없으므로, 모터마다 고유 번호(1–6)를 EEPROM에 써 줍니다. **한 번만 하면 됩니다.**

마법사 지시에 따라 **모터를 하나씩만** 보드에 연결합니다.

```text
그리퍼(6) → 손목 회전(5) → 손목 굽힘(4) → 팔꿈치(3) → 어깨 들기(2) → 베이스(1)
```

- 각 단계에서 보드에 **그 모터 하나만** 연결되어 있어야 합니다 (다른 모터와 체인 연결 X).
- 끝나면 모든 모터를 체인으로 잇고, 1번(베이스) 모터 케이블을 보드에 연결합니다.

> 이미 ID가 설정된 키트라면 이 단계는 건너뜁니다. (강사 안내 따름)

### 3-3. 캘리브레이션

**캘리브레이션 = "모터의 숫자 값"과 "실제 관절 각도"를 맞추는 작업** 입니다.

모터는 위치를 0–4095 숫자로만 압니다. 같은 자세여도 팔마다 조립 오차 때문에 숫자가 다릅니다. 캘리브레이션으로 각 팔의 **중간 위치와 움직일 수 있는 범위** 를 기록해 두면, 모든 팔이 같은 자세에서 같은 값을 내게 됩니다. 그래야 **한 팔로 모은 데이터로 학습한 모델이 다른 팔에서도 동작** 합니다.

절차:

1. 모든 관절을 **움직일 수 있는 범위의 가운데** 쯤에 둡니다. (화면 안내 그림 참고)
2. 확인을 누른 뒤, **각 관절을 한쪽 끝에서 반대쪽 끝까지 천천히** 끝까지 움직입니다.
3. 완료 후 팔을 움직여서 **화면의 3D 모델이 똑같이 움직이는지** 확인합니다.

주의:

- `wrist_roll`이 0–4095 전체 범위로 나오는 것은 정상입니다 (360° 회전 관절).
- **다른 팔의 캘리브레이션 파일을 복사하면 안 됩니다.** 오류 없이 엉뚱하게 움직입니다.
- 짝꿍이 같은 팔을 이미 캘리브레이션했다면, 내 노트북에서는 **"Skip verification"** 을 선택해 보드에 저장된 값을 읽어옵니다.

### 3-4. 리더 추가

같은 방식으로 **SO101 Leader** 추가 → 이름 `leader_<조번호>` → 모터 ID 설정(필요 시) → 캘리브레이션.

> **손목 방향 맞추기**: 리더와 팔로워의 손목(`wrist_roll`) 방향이 캘리브레이션 전에 물리적으로 맞지 않으면, 나중에 특정 각도에서 손목이 튑니다. 두 팔의 손목을 같은 방향으로 맞춘 뒤 캘리브레이션하세요.

## 4. (강사·선택) USB 이름 고정 — udev 규칙

재부팅하면 `/dev/ttyACM0`과 `ttyACM1`이 서로 바뀔 수 있습니다. 보드 시리얼 번호로 고정 이름을 만들어 두면 안전합니다.

```bash
udevadm info -a -n /dev/ttyACM0 | grep -E 'idVendor|idProduct|serial' | head -5
```

확인한 값으로 규칙 파일 작성:

```bash
sudo nano /etc/udev/rules.d/99-lerobot.rules
```

```text
SUBSYSTEM=="tty", ATTRS{serial}=="<팔로워 보드 시리얼>", SYMLINK+="so101_follower"
SUBSYSTEM=="tty", ATTRS{serial}=="<리더 보드 시리얼>", SYMLINK+="so101_leader"
```

```bash
sudo udevadm control --reload-rules && sudo udevadm trigger
ls -l /dev/so101_*
```

## 더 해보기 (경험자) — LeRobot CLI로 같은 작업

Studio가 GUI로 해 주는 일을 LeRobot 명령으로 하면 이렇습니다. 내부에서 무슨 일이 일어나는지 이해하는 데 좋습니다.

```bash
lerobot-find-port
lerobot-setup-motors --robot.type=so101_follower --robot.port=/dev/ttyACM0
lerobot-calibrate --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=follower_03
lerobot-calibrate --teleop.type=so101_leader --teleop.port=/dev/ttyACM1 --teleop.id=leader_03
```

> Studio 컨테이너가 켜져 있으면 포트를 점유하므로, 이 실습은 Studio를 끈 상태(`docker compose down`)에서 별도 Python 환경으로 합니다.
