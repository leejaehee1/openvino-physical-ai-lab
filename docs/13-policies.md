# 13. 로봇 정책(Policy) 한눈에 보기 — ACT부터 VLA까지

> "정책"은 로봇의 두뇌, 즉 **관측을 받아 행동을 내는 모델** 입니다. 13일차에 ACT 하나를 써 봤다면, 이 문서는 **어떤 정책들이 있고, 무엇이 다르며, 언제 무엇을 고르는지** 를 정리합니다.
> 기준: Physical AI Studio `main`(2026-10-19)의 정책 카탈로그와 기본 설정값, LeRobot 0.6.1의 정책 목록. 값은 소스 코드에서 확인했습니다.

## 학습 목표

- 정책의 입력·출력과 "행동 묶음(chunk)" 개념을 설명할 수 있다.
- 행동을 만드는 세 가지 방식(바로 회귀 · 확산/흐름 정합 · 토큰 생성)의 차이를 말할 수 있다.
- ACT와 VLA(SmolVLA·Pi0.5 등)의 차이를 입력·크기·데이터·엣지 실행 관점에서 비교할 수 있다.
- Studio의 학습 설정과 ACT의 주요 하이퍼파라미터가 무엇을 바꾸는지 안다.
- M6 프로젝트와 우리 장비(노트북, B70)에 맞는 정책을 근거를 들어 고를 수 있다.

---

## 1. 정책이란

```text
관측 ──▶ [ 정책 π ] ──▶ 행동
 · 카메라 영상 (1대 이상)          · 다음 관절 목표값
 · 로봇 상태 (관절값 6개)          · 보통 여러 스텝을 묶어서 (chunk)
 · (VLA만) 언어 지시 "빨간 큐브를 상자에"
```

| 용어 | 뜻 | 우리 수업 |
|---|---|---|
| 관측 (observation) | 정책이 보는 것 | `observation.images.front`, `observation.state` |
| 행동 (action) | 정책이 내는 것 | 6개 관절 목표 위치 |
| 행동 묶음 (chunk) | 한 번에 예측하는 미래 행동 수 | ACT 기본 100스텝 |
| 실행 스텝 (`n_action_steps`) | 한 번 예측해서 실제로 실행하는 스텝 수 | ACT 기본 100 (묶음 전체 실행) |
| 정책 학습 | 관측 → 행동 대응을 데이터에서 배우기 | 모방학습 (05a) |

> 정책 = 07a에서 본 **에이전트 프로그램** 입니다. "센서 입력 → 액추에이터 출력" 함수를 신경망으로 구현한 것입니다.

## 2. 행동을 만드는 세 가지 방식

같은 입력을 받아도 **행동을 어떻게 만들어 내느냐** 에 따라 정책의 성격이 크게 달라집니다.

| 방식 | 아이디어 | 대표 정책 | 장점 | 약점 |
|---|---|---|---|---|
| **① 바로 회귀** | 신경망이 행동 숫자를 **한 번에** 출력 (정답과의 차이 L1/L2로 학습) | **ACT** (+CVAE), 단순 BC | 빠름, 작음, 적은 데이터로 학습 | 정답이 여러 개(다봉성)면 평균으로 뭉개질 수 있음 |
| **② 확산 · 흐름 정합** | 무작위 잡음에서 시작해 **여러 단계에 걸쳐** 행동을 다듬어 감 | Diffusion Policy, **SmolVLA, Pi0.5** (흐름 정합) | 여러 가지 올바른 동작을 표현 가능, 부드러움 | 추론 때 여러 단계 반복 → 느림 |
| **③ 토큰 생성** | 행동을 구간으로 나눠 **번호(토큰)** 를 매기고 LLM처럼 하나씩 생성 | RT-2, Pi0-FAST, VQ-BeT(코드북) | 언어 모델 구조를 그대로 활용 | 연속값을 잘게 나누는 데서 정밀도 손실, 토큰 수만큼 느림 |

### 쉬운 비유

- **① 회귀**: "정답 위치를 한 번에 찍어라." 시험 문제에 답 하나를 쓰는 방식.
- **② 확산·흐름 정합**: "흐릿한 낙서에서 시작해 10번 고쳐 그려서 완성하라." 그래서 여러 정답 중 하나를 또렷하게 그릴 수 있습니다.
- **③ 토큰 생성**: "동작을 단어처럼 하나씩 말하라." 09에서 본 다음 토큰 예측을 동작에 적용한 것.

> 05a의 **다봉성** 문제(왼쪽으로 돌든 오른쪽으로 돌든 둘 다 정답)를 기억하나요? ①은 데이터에서 전략을 통일해 피하고(ACT는 CVAE로 일부 완화), ②는 구조 자체로 여러 정답을 표현합니다.

## 3. Studio에서 고를 수 있는 정책 (2026-10 `main` 기준)

Studio의 학습 화면에는 아래 정책이 나옵니다(해당 정책의 추가 패키지가 설치된 경우에만). **최소 VRAM** 은 Studio 소스 코드에 적힌 값입니다.

| 정책 | 종류 | 행동 생성 | 최소 VRAM | 라이선스 | 한 줄 설명 |
|---|---|---|---|---|---|
| **ACT** | 작업 특화 정책 | ① 회귀 + CVAE | **2 GB** | BSD 3-Clause | 가볍고 학습이 빠름. **우리 수업의 기본** |
| **SmolVLA** | 소형 VLA | ② 흐름 정합 | **3 GB** | Apache 2.0 | SmolVLM2-500M 기반, 언어 지시를 받음 |
| Pi0.5 | 대형 VLA | ② 흐름 정합 | 40 GB | Gemma | 더 긴 문맥, 범용성 높음 |
| RLDX-1 | 로봇 파운데이션 모델 | ② 흐름 정합 | 40 GB | RLWRLD Model License | Qwen3-VL-8B 기반, 정교한 조작 |
| XR0 | VLA | ② 흐름 정합 | 60 GB | Apache 2.0 | Qwen3-VL 기반 + 행동 전문가 |
| MolmoAct2 | VLA | ② 흐름 정합 | 80 GB | Apache 2.0 | 흐름 정합 행동 생성 VLA |

- 학습 라이브러리(`physicalai-train`)에는 이 외에도 Cosmos 3 등이 있고, **LeRobot 정책 전체**(Diffusion Policy, VQ-BeT, Pi0, Pi0-FAST, GR00T, TD-MPC 등)를 래퍼로 쓸 수 있습니다.
- ⚠️ 우리 B70에서 어떤 정책까지 학습할 수 있는지는 **B70의 VRAM 용량을 확인해 위 표와 비교** 합니다. 40 GB 이상을 요구하는 정책은 단일 GPU로는 어려울 가능성이 큽니다.
- 라이선스도 정책 선택의 일부입니다. 상업적 사용을 고려한다면 특히 확인합니다.

## 4. ACT 자세히 — 우리가 쓰는 정책의 설정값

### 4-1. 구조 복습 (06 2절)

```text
카메라 ─▶ ResNet-18 ─┐
                     ├─▶ Transformer 인코더(4층) ─▶ 디코더(1층) ─▶ 100스텝 × 6관절
관절값 ──────────────┤
(학습 때만) CVAE 잠재변수 z(32차원) ─┘
```

### 4-2. Studio 라이브러리의 ACT 기본값

| 설정 | 기본값 | 뜻 | 바꾸면 |
|---|---|---|---|
| `chunk_size` | 100 | 한 번에 예측하는 미래 스텝 수 (30fps면 약 3.3초) | 늘리면 부드럽지만 반응이 느려짐, 줄이면 반응은 빠르지만 오차 누적↑ |
| `n_action_steps` | 100 | 예측한 묶음 중 실제로 실행하는 스텝 수 | 줄이면 더 자주 다시 예측 (추론 비용↑, 상황 변화에 민첩) |
| `n_obs_steps` | 1 | 몇 프레임의 관측을 넣을지 | ACT는 현재 1프레임만 봄 |
| `vision_backbone` | resnet18 | 이미지 특징 추출기 (10 참고) | 큰 백본은 느리고 데이터가 더 필요 |
| `dim_model` | 512 | 트랜스포머 내부 벡터 크기 | 모델 크기·속도에 직결 |
| `n_encoder_layers` / `n_decoder_layers` | 4 / 1 | 블록 수 (원래 구현 버그 때문에 디코더 1층이 기본) | |
| `use_vae` / `latent_dim` | True / 32 | CVAE 사용 여부와 z 크기 (06 2절) | 끄면 여러 사람 데이터에서 평균화가 심해질 수 있음 |
| `kl_weight` | 10.0 | 손실 = 재구성 오차 + 10 × KL | |
| `temporal_ensemble_coeff` | 없음 | 겹치는 묶음들을 지수 가중 평균 (켜려면 `n_action_steps=1`) | 동작이 더 매끄럽지만 매 스텝 추론 → 엣지 부담↑ |

### 4-3. 묶음을 어떻게 실행하나 — 세 가지 방식

```text
(a) 묶음 전체 실행 (기본: n_action_steps = chunk_size = 100)
    예측 ████████████████  → 100스텝 다 실행 → 다시 예측
    + 추론 횟수 최소 (엣지에 유리)   − 묶음이 바뀌는 순간 멈칫할 수 있음

(b) 일부만 실행 (예: n_action_steps = 25)
    예측 ████████████████  → 25스텝 실행 → 다시 예측
    + 상황 변화에 빨리 반응           − 추론 4배

(c) 시간 앙상블 (n_action_steps = 1, temporal_ensemble_coeff 지정)
    매 스텝 예측, 겹치는 예측들을 가중 평균
    + 가장 매끄러움                   − 매 스텝 추론 (30fps면 초당 30회)
```

12의 예제 3으로 잰 추론 시간과 함께 보면, **우리 노트북에서 어떤 실행 방식이 가능한지** 숫자로 판단할 수 있습니다. 예를 들어 추론이 45ms라면 (c)의 33ms 주기는 감당하기 어렵고, (a)·(b)가 현실적입니다.

## 5. VLA 자세히 — 말을 알아듣는 정책

### 5-1. 구조

```text
카메라 영상 ─▶ 비전 인코더 ─┐
언어 지시   ─▶ 토큰화 ──────┼─▶ 언어 모델(VLM) ─▶ 행동 전문가(흐름 정합, 10단계) ─▶ 50스텝 묶음
로봇 상태   ─▶ (패딩, 최대 32차원) ┘
```

| | SmolVLA (Studio 기본값) | Pi0.5 (Studio 기본값) |
|---|---|---|
| 바탕 모델 | SmolVLM2-500M | Gemma 계열 |
| `chunk_size` / `n_action_steps` | 50 / 50 | 50 / 50 |
| 흐름 정합 단계 | 10 | 10 |
| 상태·행동 최대 차원 | 32 (짧으면 0으로 채움) | — |
| 사전 훈련 | 대량의 로봇 시연 데이터 | 대량의 로봇 시연 데이터 |

### 5-2. ACT와 무엇이 다른가

| | **ACT** | **VLA** (SmolVLA 등) |
|---|---|---|
| 입력 | 영상 + 상태 | 영상 + 상태 + **언어 지시** |
| 작업 수 | 정책 하나 = 작업 하나 | 정책 하나로 **여러 작업** (문구로 구분, 11의 설계 ③) |
| 출발점 | 처음부터 학습 (백본만 ImageNet 사전학습) | **로봇 데이터로 사전 훈련된 모델을 미세 튜닝** (09 2절) |
| 크기 | 작음 (수천만 파라미터급) | 수억~수십억 파라미터 |
| 데이터 | 작업당 50개 안팎 | 사전 훈련 덕분에 적은 데이터로도 가능하지만 학습 자원이 큼 |
| 학습 | 빠름 (최소 VRAM 2 GB) | 느림, VRAM 많이 필요 |
| 추론 | 1회 순전파 | 흐름 정합 10단계 반복 → 느림 |
| Hugging Face 토큰 | 필요 없음 | 모델 다운로드에 필요 (Studio 문서) |

> **정리**: ACT는 "한 가지 일을 빠르게 잘하는 숙련공", VLA는 "말귀를 알아듣는 다재다능한 신입". 엣지에서 실시간으로 한 작업을 반복한다면 ACT, 여러 작업을 말로 바꿔 시키고 싶다면 VLA가 맞습니다.

## 6. Studio 학습 설정 — 무엇을 바꾸나 (06 학습 화면)

| 설정 | 의미 | 조정 기준 |
|---|---|---|
| **batch size** | 한 번에 학습하는 샘플 수 | VRAM이 부족(OOM)하면 줄임. 너무 작으면 학습이 불안정 |
| **training steps** | 총 학습 반복 수 | loss 곡선이 평평해질 때까지. 너무 길면 과대적합 |
| **data workers** | 데이터 읽기 병렬 수 | CPU·RAM이 부족하면 줄임 |
| **precision** | 숫자 정밀도 (예: 32비트, 16비트 혼합) | 낮추면 메모리·속도 이득, 드물게 불안정 |
| **compile model** | 학습 전 모델 컴파일 | 첫 시작은 느려지고 이후 빨라질 수 있음 |
| **중단(interrupt)** | 학습 도중 멈춤 | 그 시점 체크포인트로 저장·내보내기 됨 (06) |

### loss 곡선 읽기

| 모양 | 의미 | 대응 |
|---|---|---|
| 꾸준히 내려가다 평평해짐 | 정상 | 평평해진 뒤 조금 더 학습하고 멈춤 |
| 처음부터 거의 안 내려감 | 데이터·설정 문제 | 데이터셋 확인(11), 학습률·배치 확인 |
| 크게 출렁임 | 배치가 너무 작거나 학습률이 큼 | 배치를 키우거나 학습률을 낮춤 |
| 학습은 내려가는데 로봇은 못함 | 학습 데이터에 과적합, 장면 차이 | 12의 예제 5(오프라인 검증) → 05a 체크리스트 |

> loss가 낮다고 로봇이 잘하는 것은 아닙니다(05a의 분포 이동). **최종 판단은 항상 실물 성공률**(06 6절)로 합니다.

## 7. 어떤 정책을 고를까

### 7-1. 결정 순서

```text
1. 언어로 여러 작업을 바꿔 시켜야 하나?
      아니오 → ACT (작업마다 정책 하나, M6 판단 계층이 고름: 12 예제 11)
      예     → 2로
2. 학습 GPU의 VRAM이 충분한가? (3절 표)
      SmolVLA(3 GB)까지만 → SmolVLA
      40 GB 이상         → Pi0.5 등도 후보
3. 노트북에서 실시간으로 돌아야 하나?
      예 → 12 예제 3으로 실제 지연을 재 보고 결정 (흐름 정합 10단계는 무거움)
```

### 7-2. M6 주제별 추천

| M6 주제 | 추천 정책 | 이유 |
|---|---|---|
| ★ 물체 집어 옮기기 | ACT | 한 작업, 엣지 실시간, 이미 학습 경험 있음 |
| ★★ 색깔별 분류 | ACT 2개 + 규칙 판단 / 또는 SmolVLA 도전 | ACT 조합이 안정적, VLA는 경험자 조의 도전 과제 |
| ★★ 불량품 골라내기 | ACT ("치우기" 하나) | 판정은 Anomalib이 담당, 정책은 동작만 |
| ★★★ 말로 시키는 로봇 | ACT 여러 개 + 로컬 LLM이 선택 (권장) / SmolVLA | LLM(M4)이 언어를, ACT가 동작을 맡는 분업이 엣지에서 현실적 |

> **분업 vs 통합**: VLA는 언어 이해와 동작을 **한 모델에 통합** 합니다. 반대로 "로컬 LLM + 작은 ACT 여러 개"는 **분업** 입니다. 엣지에서는 분업이 가볍고 고장 난 부분을 찾기 쉽고, 통합은 처음 보는 지시에 더 유연합니다. 이 비교 자체가 좋은 M6 발표 주제입니다.

| 단계 | 방법 | 문서 |

## 9. 자기점검

1. ACT의 `chunk_size=100`, `n_action_steps=100`은 각각 무엇을 뜻하나요?
2. 회귀 방식 정책이 다봉성 데이터에서 약한 이유와, 확산·흐름 정합 방식이 이를 어떻게 다루나요?
3. 시간 앙상블을 켜면 동작은 매끄러워지지만 엣지에서 부담이 커지는 이유는?
4. ACT와 VLA의 입력 차이는 무엇이고, 그 차이가 M6 설계에 어떤 영향을 주나요?
5. Studio에서 Pi0.5를 고르기 전에 확인해야 할 것 두 가지는?
6. loss가 충분히 낮은데 로봇이 실패한다면 무엇부터 의심하나요?
7. "로컬 LLM + ACT 여러 개"와 "VLA 하나"의 장단점을 한 가지씩 말해 보세요.

<details>
<summary>모범 답안</summary>

1. 한 번에 앞으로 100스텝의 행동을 예측하고, 그 100스텝을 모두 실행한 뒤 다시 예측한다는 뜻입니다.
2. 같은 상황에 정답이 여러 개면 회귀는 그 평균을 내서 어느 정답도 아닌 동작을 할 수 있습니다. 확산·흐름 정합은 잡음에서 시작해 여러 단계로 다듬으며 정답 중 하나를 또렷하게 만들어 내므로 여러 정답을 표현할 수 있습니다.
3. 매 스텝마다 새로 예측해야 하므로 30fps면 초당 30번 추론해야 합니다. 추론이 33ms보다 길면 제어 주기를 맞출 수 없습니다.
4. VLA는 언어 지시를 함께 받습니다. 그래서 정책 하나로 여러 작업을 문구로 구분할 수 있고, ACT는 작업마다 정책을 따로 두고 판단 계층이 골라야 합니다.
5. 학습 GPU의 VRAM이 최소 요구량(40 GB)을 넘는지, 그리고 라이선스(Gemma)와 Hugging Face 토큰 같은 사용 조건입니다.
6. 학습 데이터와 실행 환경의 차이(카메라 위치, 조명, 시작 자세)와 불량 에피소드를 먼저 의심합니다. 오프라인 검증으로 데이터 장면에서는 잘 맞는지 확인합니다.
7. 분업: 가볍고 어느 부분이 고장 났는지 찾기 쉽지만, 정해진 동작 밖의 지시는 못 합니다. VLA: 새로운 지시에 유연하지만 무겁고 학습·추론 자원이 많이 듭니다.

## 용어 사전

| 용어 | 뜻 |
|---|---|
| 정책 (policy) | 관측을 받아 행동을 내는 모델 |
| 행동 묶음 (action chunk) | 한 번에 예측하는 여러 스텝의 행동 |
| `n_action_steps` | 예측한 묶음 중 실제로 실행하는 스텝 수 |
| 시간 앙상블 | 매 스텝 예측한 겹치는 묶음들을 가중 평균해 부드럽게 만드는 방법 |
| CVAE | 시연의 스타일을 잠재변수로 요약하는 조건부 변분 오토인코더 (ACT) |
| 확산 정책 | 잡음에서 여러 단계로 행동을 다듬어 생성하는 정책 |
| 흐름 정합 (flow matching) | 잡음에서 행동으로 가는 경로를 학습해 적은 단계로 생성하는 방법 (SmolVLA, Pi0.5) |
| VLA | Vision-Language-Action. 영상·언어를 받아 행동을 내는 모델 |
| 파운데이션 모델 | 대량 데이터로 사전 훈련되어 미세 튜닝의 출발점이 되는 모델 |
| VRAM | GPU 메모리. 학습 가능한 모델 크기를 결정 |
